## 0. 이 문서를 읽기 전에 알아야 할 핵심

### 0.1 CRA는 무엇을 규제하는가?

CRA는 EU 시장에 공급되는 하드웨어·소프트웨어 제품 중 디지털 요소가 있고, 의도된 목적 또는 합리적으로 예견 가능한 사용에 장치나 네트워크와의 직접·간접 데이터 연결이 포함되는 제품을 대상으로 사이버보안 요구사항을 정한 EU 규정이다.

쉽게 말하면, 제품을 판매할 때 한 번 보안 점검하는 데 그치지 않는다. 제품을 설계하고 생산할 때부터 보안을 고려하고, 출하 후 취약점이 발견되면 처리하고, 보안 업데이트를 제공하며, 지원기간과 사용자 안내를 관리하도록 요구한다.

CRA가 모든 제품에 똑같은 보안 기능을 설치하라고 명령하는 것은 아니다. 제조자는 제품의 용도, 기능, 연결 방식, 사용 환경과 위험을 평가하고, 법령 요구사항을 제품에 맞게 충족했음을 증거로 설명해야 한다.

### 0.2 인터넷에 연결되지 않으면 CRA 대상이 아닌가?

그렇게 단정할 수 없다. 인터넷 연결만이 데이터 연결은 아니다. 산업용 필드버스, Ethernet, USB 설정·진단 연결, 시리얼 통신 등도 실제로 디지털 정보를 주고받는다면 CRA의 데이터 연결 판단에 중요할 수 있다.

다만 전원 공급, 단순 전기 신호 또는 데이터로 인코딩·해독되지 않는 단순 스위칭 신호만으로 자동 적용된다고 볼 수도 없다. 실제 인터페이스의 목적과 데이터 교환 방식을 확인해야 한다.

### 0.3 EtherCAT 포트가 있으면 자동으로 중요 제품(Class I)인가?

아니다. CRA Annex III Class I에는 'Physical and virtual network interfaces' 카테고리가 있지만, 제품 전체의 핵심 기능(core functionality)이 해당 기술 설명에 부합하는지 판단해야 한다. 서보 드라이브에 EtherCAT 인터페이스가 내장되어 있다는 사실만으로 서보 드라이브 전체가 네트워크 인터페이스 제품으로 자동 분류되는 것은 아니다.

반대로 별도로 판매되는 네트워크 인터페이스 모듈이나 네트워크 연결 기능 자체가 제품의 핵심 기능인 장치는 별도 판단이 필요하다. 이 구분은 Commission Implementing Regulation (EU) 2025/2392의 핵심 기능 접근과 일치한다.

### 1.2 현행 계열과 과거 제품/도구를 구분한다

제조사 공개 제품 페이지의 목록에는 L7SA/L7SB, L7PA/L7PB 등 세부 계열이 표시되어 있다. 한편 제조사 매뉴얼 페이지에는 과거 L7S DRIVE 매뉴얼도 남아 있다. 제조사 DriveCM 안내 페이지는 DriveCM 지원 계열과 함께 L7S 및 L7N 구형 제품은 LIVE i.C.E를 사용한다고 별도로 안내한다.

- **L7SA/L7SB**와 과거 명칭 **L7S**를 동일한 HW/FW/통신 사양이라고 가정하지 않는다.

- 매뉴얼이 홈페이지에 남아 있다는 사실은 해당 제품이 현재 신규 판매 중이거나 보안 지원 중이라는 증거가 아니다.

다음 자료를 확인해야 한다.

1. LS메카피온 제품을 EU 고객에게 직접 판매하는가?
2. EU 내 수입자·유통사·현지 법인·대리인이 있는가?
3. OEM/ODM 제품을 다른 회사 상표로 판매하는가?
4. 제품을 무상 샘플·평가용으로 공급하는가? 상업 활동의 일부인지 확인한다.
5. 제품을 기계 제조사에 부품으로 공급하는가? 단순 부품 공급이라는 이유만으로 CRA에서 자동 제외되는 것은 아니다.
6. EU 시장에 처음 공급된 날짜와 그 이후 실질적 변경 이력을 추적할 수 있는가?

**현재 결론:** EU 공급 경로·시장 출시 시점에 대한 제조사 증거가 없으므로 LS메카피온 각 계열의 EU 시장 공급 사실은 Unknown이다.

| 아날로그 지령 | ±10V 등 모델별 가능성 | 아날로그 전압 신호만으로 디지털 데이터 연결이라고 단정하지 않음 |
| DI/DO | Ready, Alarm, Enable 등 | 단순 접점·스위칭과 정보 인코딩·통신을 구분 |
| 엔코더 피드백 | 모터 위치·속도 피드백 | 제품 내부/외부 경계, 디지털 프로토콜 및 데이터 교환을 확인 |
| PC 설정 도구 | DriveCM 또는 LIVE i.C.E | 도구가 독립 제품인지, 드라이브의 의도된 사용에 필수인지, 펌웨어/파라미터에 어떤 권한을 갖는지 확인 |
| 원격 서비스/클라우드 | 현재 공개자료만으로 확인되지 않음 | 제조자 책임의 원격 데이터 처리 솔루션인지, 제품 기능에 필수인지 확인 |

**잠정 판단:** EtherCAT 통신형 계열은 CRA의 제품 디지털 요소 및 데이터 연결 정의에 들어갈 가능성이 높다. 펄스/아날로그 계열도 서비스·설정·진단용 디지털 인터페이스, 디지털 명령 또는 제공 소프트웨어의 연결 방식에 따라 적용될 수 있으므로 계열명만으로 제외하지 않는다.

### 2.3 세 번째 질문 — 제품 경계는 어디까지인가?

초보자가 가장 많이 놓치는 부분이다. 서보드라이브 본체만 떼어놓고 보면 안 된다.

예를 들어 다음 구성을 생각한다.

```
상위 PLC / Motion Controller
          |
       EtherCAT
          |
    LS 서보드라이브
      |         |
   서보모터   엔코더
      |
PC 설정·진단 도구(DriveCM 등)
      |
펌웨어/설정 파일 배포 경로
```

각 구성요소가 자동으로 하나의 제품이 되는 것은 아니다. 제조자가 의도한 기능, 판매·배포 방식, 필수 소프트웨어 여부, 기능 의존성을 근거로 제품 경계를 정해야 한다.

- 드라이브 내부 펌웨어와 부트로더는 제품의 디지털 기능을 수행하는 핵심 구성요소로 평가한다.
- PC 설정 도구가 별도 제품으로 제공되는지, 드라이브 사용을 위해 필수로 제공되는지 확인한다.
- 펌웨어 파일과 ESI 파일은 각각 실행 코드/장치 설명 파일인지 구분한다.
- 제조자 책임의 서버·클라우드가 드라이브의 기능을 수행하는 데 필수라면 Remote Data Processing Solution(RDPS) 여부를 검토한다.
- 단순히 외부 클라우드에 연결할 수 있다는 이유만으로 RDPS라고 결론 내리지 않는다.

## 3. 중요 제품·핵심 제품(Annex III/IV) 분류

### 3.1 '중요 제품'은 위험해 보이는 제품이라는 뜻이 아니다

CRA는 Annex III와 Annex IV에 특정 제품 카테고리를 열거한다. 제품이 해당 목록의 기술적 설명과 핵심 기능에 부합하면 더 엄격한 적합성 평가 절차가 적용될 수 있다.

즉, 위험도가 높아 보인다는 주관적 이유만으로 Class I 또는 Class II가 되는 것이 아니다. 반대로 제품에 네트워크 포트가 있다는 이유 하나만으로 Class I이 되는 것도 아니다.

### 3.2 LS 서보드라이브와 관련해 특히 확인할 Annex III 항목

| Annex III 후보 | 법령상 기술적 의미 | LS 서보드라이브 예비 판단 |
|---|---|---|
| Class I Category 10 — Physical and virtual network interfaces | 장치와 네트워크를 연결하는 물리/가상 네트워크 인터페이스. 2025/2392는 Ethernet, USB, Bluetooth, Fieldbus 등 인터페이스 사례를 포함 | EtherCAT 인터페이스가 내장된 드라이브는 경계 사례다. 드라이브 전체의 핵심 기능이 네트워크 인터페이스인지, 네트워크 인터페이스는 모터 제어 제품의 구성요소인지 확인해야 한다. 내장 포트만으로 자동 분류하지 않음 |
| Class I Category 11 — Operating systems | 하드웨어 추상화·프로그램 실행·자원 관리 등을 제공하는 운영체제. 실시간 운영체제도 기술 설명에 포함 | 드라이브 내부에 RTOS 또는 OS 구성요소가 있다는 것만으로 드라이브 전체가 운영체제 제품이 되지는 않는다. 독립 제품/핵심 기능 여부 확인 |
| Class I Category 14 — Microcontrollers with security-related functionalities | 다른 제품·네트워크·서비스를 보호하는 암호화, 인증, 보안 키 저장, 난수, TEE 등 보안 관련 기능을 제공하는 MCU | 일반 제어 MCU를 자동 분류하지 않는다. 실제 부품번호와 보안 기능, 그 MCU 자체의 제품 경계 및 핵심 기능 확인 |
| Class I Category 15 — ASIC/FPGA with security-related functionalities | 보안 관련 기능을 갖는 ASIC/FPGA | FPGA가 있다는 사실만으로 분류하지 않는다. 보안 기능과 제품 경계 확인 |
| Class I Category 6 — Network management systems 등 | 네트워크 관리가 핵심 기능인 시스템 | DriveCM이 파라미터 설정/모니터링 도구라는 사실만으로 네트워크 관리 시스템이 되는 것은 아니다. 독립 제품의 실제 핵심 기능을 확인 |

Annex IV도 전 항목을 제품 전체의 핵심 기능과 대조해야 한다. 현재 확인한 LS 제품 공개 설명만으로는 전형적인 서보드라이브가 Annex IV 카테고리의 핵심 기능을 수행한다고 볼 근거가 없다. 그러나 모델·옵션·별도 제품 경계를 확인하지 않은 상태이므로 Annex IV 비해당을 확정하지 않는다.

### 3.3 이 단계의 분류 결론

- LS메카피온 서보드라이브가 일반적인 모터 위치·속도·토크 제어를 핵심 기능으로 하는 제품이라면, 우선 일반 CRA 제품(PDE) 경로로 분석하는 것이 합리적이다.
- EtherCAT 포트·USB·내부 MCU·RTOS를 보유했다는 사실만으로 Annex III Class I/II 또는 Annex IV로 자동 분류하지 않는다.
- 다만 EtherCAT 네트워크 인터페이스 자체가 독립 판매되는지, 보안 기능 MCU/FPGA가 독립 제품인지, 특정 모델이 네트워크 인터페이스·운영체제 등 카테고리의 핵심 기능을 수행하는지 별도 검토한다.
- 최종 분류는 정확한 모델·주문코드·사용 목적·제품 경계·하드웨어/펌웨어 자료를 확보한 후 승인한다.

## 5. 서보드라이브 제조사가 준비해야 하는 CRA 요구사항

다음은 법령 요구를 서보드라이브의 기술·운영 업무로 번역한 것이다. 특정 기술을 무조건 구현하라는 의미가 아니라, 제품 위험평가 결과에 따라 적용·비적용·대체 통제를 정하고 증거를 남겨야 한다.

### 5.1 제품 위험평가와 보안 설계 — Article 13, Annex I Part I

| CRA 요구 | 쉬운 설명 | 서보드라이브에서 확인할 사항 | 필요한 증거 예 |
|---|---|---|---|
| 위험에 비례한 보안 수준 | 제품의 사용 환경과 위험에 맞는 보안 설계 | PLC/산업망/엔지니어링 PC 연결, 명령·파라미터·펌웨어 공격 시나리오 | 위험평가서, 위협 모델 |
| 알려진 악용 가능 취약점 없는 출시 | 이미 알려진 위험한 취약점을 방치한 채 출하하지 않도록 관리 | MCU, RTOS, 통신 스택, 부트로더, PC 도구, 라이브러리 취약점 점검 | SBOM, 취약점 스캔, 출시 승인 |
| Secure by default | 기본 설정부터 안전해야 함 | 초기 계정/비밀번호, 서비스 포트, 불필요한 프로토콜, 원격 기능 기본 비활성화 여부 | 기본 설정표, 초기화 시험 |
| 보안 업데이트 | 취약점을 수정할 수 있는 업데이트 제공 | 펌웨어 업데이트 경로, 무결성·진위 검증, 실패 복구, 호환성 | 업데이트 설계서, 시험 로그 |
| 인증·접근통제 | 권한 없는 사람이 설정·제어하지 못하도록 함 | DriveCM 접속, 파라미터 변경, 펌웨어 다운로드, 서비스 권한 | 권한 매트릭스, 인증 시험 |
| 기밀성 | 보호할 데이터가 노출되지 않도록 함 | 자격증명, 키, 설정 파일, 진단 데이터의 저장·전송 | 데이터 분류, 암호화 설계 |
| 무결성 | 명령·프로그램·설정이 허가 없이 변조되지 않도록 함 | 위치/속도/토크 지령, 파라미터, 펌웨어, ESI·설정 파일의 신뢰성 | 서명/검증 설계, 변조 시험 |
| 가용성·복원력 | 공격이나 오류 후에도 필수 기능을 보호 | 통신 폭주, 비정상 프레임, DoS, 통신 단절, 안전한 정지/복구 동작 | 부하·장애 시험, 복구 시험 |
| 공격 표면 축소 | 불필요한 포트·서비스를 줄임 | USB/시리얼/Ethernet 디버그·서비스 포트, 사용하지 않는 프로토콜 | 인터페이스 인벤토리, 설정 검사 |
| 사고 영향 완화 | 침해가 발생해도 피해 범위를 제한 | 파라미터 변경 권한, 축별/드라이브별 격리, 네트워크 분할, 제한된 서비스 권한 | 설계 검토, 침해 시나리오 시험 |
| 보안 로그 | 보안 관련 접근·변경을 추적 | 파라미터 변경, 로그인, 펌웨어 업데이트, 오류·보안 이벤트 | 로그 명세, 로그 시험 |
| 데이터·설정 삭제 | 사용자가 저장 데이터와 설정을 안전하게 제거 | 사용자 설정 초기화, 서비스 계정/키 제거, 양도·폐기 절차 | 초기화·삭제 시험 |

**구현 기술과 법적 요구의 구분:** Secure Boot, 디지털 서명, MFA, RBAC, 특정 암호 알고리즘, immutable log, SIEM 등은 위험을 줄이기 위한 설계 후보일 수 있다. CRA가 모든 서보드라이브에 이 특정 기술을 일률적으로 명령한다고 표현하지 않는다. 제조자는 위험평가와 제품 특성에 따라 적절한 방법을 선택하고 효과를 검증해야 한다.

### 5.2 취약점 처리와 업데이트 — Annex I Part II

제조사의 의무는 제품 출하 시점에 끝나지 않는다.

1. 제품과 구성요소를 식별하고, 일반적으로 사용되는 기계 판독 형식의 SBOM을 작성한다. 최소한 최상위 의존성을 포함하도록 관리한다.
2. 제품 내 취약점을 지체 없이 처리하고 보안 테스트·검토를 수행한다.
3. 취약점 제보를 받을 공개 연락 경로와 coordinated vulnerability disclosure(CVD) 절차를 마련한다.
4. 취약점 수정 사항과 보안 업데이트를 안전하게 배포한다.
5. 식별된 보안 이슈를 다루는 보안 업데이트의 무상 제공 의무 및 법령상 예외를 확인한다.
6. 업데이트의 진위·무결성, 설치 실패·전원 차단·통신 단절 시 복구, 이전 버전으로의 위험한 다운그레이드 가능성을 시험한다.

### 5.3 지원기간 — Article 13(8), 13(9)

지원기간은 모든 제품에 무조건 5년을 적용하는 단순 규칙이 아니다. 예상 사용기간, 사용자의 합리적 기대, 제품의 성격과 관련 법령을 고려해야 한다. 최소 5년 원칙이 있지만 예상 사용기간이 5년보다 짧은 제품에는 법령상 예외가 있다.

산업용 서보드라이브는 설비에 장기간 설치될 수 있으므로, 제조자는 다음을 근거로 지원기간을 정해야 한다.

- 제품군별 예상 사용기간과 고객 설비의 교체주기
- 펌웨어·운영체제·통신 스택·제3자 라이브러리 지원기간
- 부품 공급과 수리 가능 기간
- 보안 업데이트 개발·검증·배포 가능 기간
- 지원 종료일 안내와 EOL 공지 정책

지원기간 중 제공한 각 보안 업데이트는 발행 후 최소 10년 또는 지원기간 잔여기간 중 더 긴 기간 동안 이용 가능해야 한다. 이는 제조사의 지원기간을 무조건 10년으로 정하라는 뜻과 다르다.

### 5.4 사용자 정보·기술문서·CE — Annex II, Annex VII, Articles 28–32

사용자에게는 제품 식별, 제조자 연락처, 의도된 목적, 안전한 설치·운영·업데이트·폐기 지침, 지원 종료일 등 필요한 정보를 제공해야 한다.

기술문서에는 제품 설명, HW/FW 구성, 설계·개발·생산 정보, 취약점 처리 프로세스, SBOM 관련 정보, 위험평가, 지원기간 근거, 적용 표준, 시험 보고서 및 EU DoC 등 법령이 요구하는 정보를 연결해야 한다.

일반 제품의 적합성 평가 절차는 Article 32(1)에 따라 Module A, Module B+C, Module H 또는 해당되는 EU 사이버보안 인증 절차를 검토한다. Annex III/IV 제품으로 판정되면 Article 32(2)~(4)의 더 엄격한 절차를 적용한다. **분류가 확정되기 전에 Module A만으로 충분하다고 결론 내리지 않는다.**

### 6.1 안전 기능과 사이버보안 기능은 구분한다

STO(Safe Torque Off) 등 기능안전 기능이 존재하더라도 CRA 사이버보안 요구사항을 자동 충족하지 않는다. STO 인증 또는 SIL/PL 자료는 기능안전 증거이며, 인증·권한·펌웨어 무결성·취약점 처리·보안 업데이트 증거와 별도로 관리해야 한다.

반대로 사이버보안 통제가 모터 제어·정지·복구 동작에 영향을 줄 수 있으므로, 보안 설계 변경은 기능안전·기계 안전 담당자와 인터페이스를 검토해야 한다. 이 보고서는 SIL 3 설계 또는 안전 무결성 수준을 평가하지 않는다.

PR #99/#100의 live canary에서는 10개 HTML 출처와 3개 PDF 자료의 수집·해시를 확인했다. PR #102에서는 10개 HTML 출처 provenance manifest의 JSON 파싱·round-trip 검증을 확인했다.

현재 source pack의 주요 문서 범위는 다음과 같다.

1. Regulation (EU) 2024/2847 CRA 본문 및 Annex I–VIII.
2. CRA 공식 정오표 3건(2024-12-05, 2025-07-02, 2025-10-17).

### 10.2 '법령을 모두 수집했다'고 말할 수 없는 이유

현재 source pack은 CRA 직접 관련성이 높은 주요 법령·공식 자료를 관리하지만, CRA와 함께 적용될 수 있는 모든 제품별 EU 법령·표준·최신 ENISA 자료를 완전하게 수집·검토했다고 주장할 수 없다.

추가 확인이 필요한 항목은 다음과 같다.

- CRA FAQ·ENISA Single Reporting Platform FAQ 최신판과 신고 플랫폼 절차 변경.
- M/606 41개 표준 항목의 최신 일정 및 CEN/CENELEC/ETSI 산출물의 실제 발행 상태.

## 15. 2026-11-19 추가 조사 — 최신 CRA 지침 및 표준화 일정

### 15.1 유럽위원회 CRA 적용 지침 — OJ C/2026/6013 (승인 문서 C(2026) 5252)

유럽위원회는 CRA 적용을 돕기 위한 공식 지침을 공개했다. 지침은 CRA Article 26에 따른 해석·실무 안내이며, CRA 규정 자체와 동일한 법적 구속력을 갖는 법령으로 취급하지 않는다.

주요 설명 범위는 다음과 같다.

- 제품이 CRA 적용 범위에 들어오는지 판단하는 방법(원격 데이터 처리 솔루션 포함)
- 자유·오픈소스 소프트웨어 관련 쟁점
- 제품의 실질적 변경(substantial modification)
- 제품 지원기간을 정하고 적용하는 방법
- 위험평가와 Article 14 신고 의무의 실무 적용
- 소규모 사업자도 활용할 수 있는 67개 실무 사례, 흐름도 및 그래프

**LS메카피온 적용 포인트:** 드라이브 펌웨어·설정 도구·서비스 도구·외부 처리 서비스의 제품 경계를 먼저 정리하고, 펌웨어 교체·기능 추가·보안 업데이트가 실질적 변경에 해당하는지 변경 이력과 기능 영향으로 평가해야 한다. 제품별 지원기간은 단순히 판매 종료일이나 보증기간과 같다고 가정하지 말고, 보안 업데이트 제공 능력과 제품 수명·사용 환경을 근거로 정해야 한다.

### 15.2 CRA 표준화 요청 M/606 개정 — 2026-11-10

유럽위원회 CRA 표준화 공식 페이지는 2026-11-10에 표준화 요청 M/606이 개정되었으며, 일부 수평 표준과 모든 수직(제품별) 표준의 제출 기한이 3개월 연장되었다고 명시한다. M/606은 CRA 지원을 위한 41개 표준을 포함한다.

이 변경은 표준 개발기관에 대한 산출물 제출 일정이다. 다음을 혼동하지 않는다.

1. 표준 초안·최종안의 제출 일정
2. 표준이 유럽조화표준으로 채택되고 EU 관보(OJ)에 인용되는 절차
3. CRA Article 27에 따른 적합성 추정(presumption of conformity)의 발생
4. CRA 자체의 법적 적용일

**표준 개발 일정이 연장됐다는 이유로 CRA의 2026-09-11 신고 의무나 2027-12-11 일반 적용일이 연장된 것은 아니다.** 또한 M/606의 표준 개발 요청에 포함된 표준을 적용했다는 사실만으로 Article 27 적합성 추정이 자동 발생하지 않는다. 해당 표준이 최종 조화표준으로 OJ에 인용되었는지, 인용 범위와 제한사항이 무엇인지 별도 확인해야 한다.

- Commission CRA standardisation page: https://digital-strategy.ec.europa.eu/en/policies/cra-standardisation
- 해당 페이지 최종 업데이트: 2026-11-12
- Commission Documents Register: C(2026) 7861 (M/606 amendment; 2026-11-10)

## 16. CRA 관련 위임규정 및 ENISA 최신 실무자료 추가 검토

### 16.1 Commission Delegated Regulation (EU) 2025/1535 — 특정 L-category 차량 제품의 CRA 제외

이 위임규정은 Regulation (EU) No 168/2013의 적용을 받는 특정 L-category 차량의 디지털 제품에 대해 CRA 적용을 제외한다. 다만 페달 보조형 L1e 차량은 이 제외에서 다시 예외로 둔다. 이 규정은 2025-10-29 관보에 게재되었고 2025-11-18 발효했다.

**서보드라이브에 대한 의미:** 일반 산업용 서보드라이브가 이 규정 때문에 CRA에서 제외되는 것은 아니다. 드라이브가 L-category 차량의 형식승인 체계에 속하는 제품인지, 차량용 시스템·부품으로 어떤 법적 지위로 공급되는지에 대한 구체적 근거가 있을 때만 검토한다. 단순히 모터나 차량 자동화에 사용된다는 이유로 제외를 적용하지 않는다.

공식 원문: https://eur-lex.europa.eu/legal-content/EN/TXT/?uri=CELEX%3A32025R1535

### 16.2 Commission Delegated Regulation (EU) 2026/881 — 신고의 전파 지연 조건

이 위임규정은 CRA Article 14에 따른 취약점·중대 사고 신고를 받은 조정 CSIRT가 사이버보안상 사유로 다른 CSIRT에 정보를 전파하는 것을 지연할 수 있는 조건과 절차를 구체화한다. 2026-04-20 관보 게재, 2026-05-10 발효 상태다.

**중요한 구분:** 이는 제조자가 Article 14에 따라 최초 신고를 해야 하는 기한을 연장하거나 면제하는 규정이 아니다. 제조자의 신고 의무와 기한은 CRA Article 14 원문 및 공식 이행 지침에 따라 별도로 관리하고, 2026/881은 신고 수신 후 CSIRT 간 정보 전파 지연에 관한 규칙으로 구분한다.

공식 원문: https://eur-lex.europa.eu/legal-content/EN/TXT/?uri=CELEX%3A32026R0881

## 17. 서보드라이브와 기계류 규정 등 다른 EU 제품법령의 관계

### 17.1 왜 CRA만 확인하면 안 되는가?

산업용 서보드라이브는 완성 기계 안에 들어가거나, 기계 제조사에 부품·부분완성기계 형태로 공급될 수 있다. 이때 제품의 법적 경계에 따라 CRA뿐 아니라 기계류·전기·전자파 등 다른 EU 제품법령도 검토해야 한다.

초보자 관점에서 다음처럼 구분한다.

- **CRA:** 디지털 요소가 있는 제품의 사이버보안, 취약점 처리, 보안 업데이트, 제조자 의무를 다룬다.
- **Machinery Regulation:** 기계 및 관련 제품의 건강·안전 요구사항을 다룬다. 제어시스템이나 소프트웨어의 사이버 공격이 안전 위험을 만들 수 있는 부분도 포함한다.
- **EMC Directive:** 전자기 방해를 발생시키거나 영향을 받는 장비의 전자파 적합성을 다룬다.
- **Low Voltage Directive:** 적용 범위의 전기 장비에 대한 전기 안전 위험을 다룬다.
- **RED:** 무선통신 기능이 포함된 무선기기라면 추가 검토한다.
- **RoHS/WEEE:** 유해물질 제한·폐전기전자제품 관리와 관련된 환경 규제다. 이 규정들이 사이버보안 요구를 대신한다고 보아서는 안 된다.

한 제품에 여러 법령이 동시에 적용될 수 있다. 제품별 적용 여부는 제품 경계, 의도된 용도, 전압·무선 기능, 공급 방식 및 시장 출시 시점을 기준으로 판단한다.

### 17.2 CRA Article 2의 제외와 다른 법령의 관계

CRA Article 2(2)~(5)는 다른 EU 법령과의 관계를 정한다.

- Article 2(2)~(4)는 의료기기·체외진단 의료기기, 특정 자동차 형식승인 제품, 인증된 항공 제품, 해양장비 등 명시된 법적 범주의 제외를 규정한다.
- Delegated Regulation (EU) 2025/1535는 Regulation (EU) No 168/2013의 적용을 받는 특정 L-category 차량 제품을 추가로 제외하되 페달 보조형 L1e 차량은 예외로 둔다.
- Article 2(5)는 다른 EU 법령이 CRA Annex I의 위험 중 일부 또는 전부를 다루는 경우에도, 전체 규제 체계와 보호수준 조건을 충족해야 적용을 제한·제외할 수 있도록 위임규정의 근거를 둔다.

**중요:** 다른 법령이 존재한다는 사실만으로 CRA가 자동 제외되는 것은 아니다. CRA Article 2가 명시한 제외 또는 그에 근거해 실제 채택된 위임규정의 제품·범위·조건을 확인해야 한다.

공식 CRA 원문: https://eur-lex.europa.eu/legal-content/EN/TXT/?uri=CELEX%3A32024R2847

### 17.3 Machinery Regulation (EU) 2023/1230 — CRA와 병행 검토

Machinery Regulation (EU) 2023/1230은 2027-01-20부터 적용된다. Annex III의 다음 요구사항은 사이버보안과 기계 안전이 만나는 부분이다.

| 조항 | 쉬운 설명 | 서보드라이브·완성 기계에 대한 검토 예 |
|---|---|---|
| Annex III 1.1.9 Protection against corruption | 외부 장치·원격 연결로 위험한 상태가 생기지 않도록 하고, 안전 관련 소프트웨어·데이터와 신호/데이터 전달 하드웨어를 훼손으로부터 보호하며, 개입·변경 증거를 수집 | PLC/네트워크를 통한 명령 변조, 안전 관련 파라미터 변경, 펌웨어·설정 무결성 |
| Annex III 1.2.1 Safety and reliability of control systems | 제어시스템이 정상·비정상 외부 영향과 합리적으로 예견 가능한 제3자 악의적 시도에도 위험 상태를 만들지 않도록 설계 | 통신 장애·악성 명령·제어 로직 오류·외부 접근이 기계의 위험 동작으로 이어지는지 |

유럽위원회 공식 CRA FAQ는 제품이 CRA의 제품 with digital elements이면서 동시에 Machinery Regulation 적용 대상이면 **두 규정의 사이버보안 및 건강·안전 요구사항을 함께 충족해야 한다**고 설명한다. CRA 요구를 충족한 사실이 Machinery Regulation의 요구를 자동으로 전부 충족시키는 것도 아니고, 반대도 아니다. 위험평가와 관련 표준·기술 사양을 이용해 공통 위험에 대한 시너지와 중복 시험의 활용 가능성을 입증할 수 있지만, 각 규정의 적합성 평가 절차도 각각 확인해야 한다.

공식 Commission FAQ:
https://digital-strategy.ec.europa.eu/en/library/cyber-resilience-act-implementation-frequently-asked-questions

FAQ는 2026-09-04 업데이트된 기술 FAQ이며, Commission services가 작성한 비권위적·비구속적 안내다. FAQ 자체가 법령 원문을 바꾸거나 추가 의무를 만들지는 않는다. 이 FAQ의 Machinery Regulation 섹션은 CRA와 기계류 규정의 병행 적용, Annex III 1.1.9/1.2.1, 개별 적합성 평가 절차를 설명한다.

**서보드라이브 단품에 대한 주의:** 서보드라이브가 기계에 설치된다는 사실만으로 드라이브 단품 자체가 자동으로 Machinery Regulation상 완성 기계가 되는 것은 아니다. 드라이브가 독립적으로 시장에 공급되는 제품인지, 기계 제조사가 조립하는 구성품인지, 특정 용도를 위해 추가 조립이 필요한 partly completed machinery인지, 안전 부품인지 등을 정의·공급 방식·제조사 문서에 근거해 판정해야 한다.

| Directive 2012/19/EU WEEE | EU 시장 공급 시 폐전기전자제품 생산자 책임·등록 등 검토 | 폐기물·환경 규제이며 CRA 보안 요구 대체 아님 |
| Regulation (EU) 2024/2853 Product Liability Directive | 제품 결함으로 인한 손해 책임과 업데이트·보안 결함의 사후 책임 맥락 | CRA와 법적 목적은 다르며 서로 보완적. 자동 면제 또는 동일 적합성 절차로 보지 않음 |

이 표는 법령 전수 목록이 아니라 서보드라이브에 대한 1차 적용성 스크리닝이다. 각 법령의 최신 개정·적용일, 조화표준, 국가별 이행 및 제품별 예외를 추가 확인해야 한다.

### 17.5 LS메카피온에 필요한 제품 경계 결정 질문

1. LS메카피온이 EU 시장에 공급하는 것은 드라이브 단품, 서보 시스템 세트, 부분완성기계, 완성 기계 중 무엇인가?
2. 드라이브의 의도된 용도와 최종 고객의 설치·조립 책임은 누구에게 있는가?
3. 드라이브가 자체적으로 특정 기계 기능을 수행하는가, 아니면 다른 기계에 통합되어야만 기능하는가?
4. 안전 관련 소프트웨어·데이터·파라미터는 무엇이며, 어떤 하드웨어/통신 인터페이스를 통해 접근할 수 있는가?
5. 무선 통신 옵션이 있는가? 있다면 모델·모듈·무선 기능·EU 판매 변형은 무엇인가?
6. 제조자·수입자·기계 제조자 간 EU 적합성 선언 및 기술문서 책임 분담은 어떻게 되는가?

현재 위 질문의 제품별 증거가 없으므로 CRA·Machinery Regulation의 적용 여부와 책임 분담은 Unknown으로 유지한다.

## 18. CRA 표준화 작업의 두 갈래 — M/606과 2026 연간 작업계획

### 18.1 M/606만 보면 전체 제품군의 표준화 계획을 놓칠 수 있다

M/606은 CRA Annex III/IV의 중요·중요(critical) 제품 카테고리를 중심으로, 모든 제품에 적용되는 수평 표준과 특정 카테고리별 수직 표준을 개발하도록 요청한 41개 표준 묶음이다. 2026-11-10 개정은 일부 수평 표준과 모든 수직 표준의 제출 일정을 3개월 연장했다.

그러나 LS메카피온 서보드라이브가 Annex III/IV 카테고리에 속하지 않는다고 판단되더라도, 표준화 검토가 끝나는 것은 아니다.

### 18.2 Commission Notice C/2026/1695 — 2026 연간 EU 표준화 작업계획 Action 5

유럽연합 관보에 2026-03-19 게재된 Commission Notice C/2026/1695는 CRA 지원 표준화 Action 5를 별도로 제시한다. 이 계획은 M/606을 보완하며, CRA Annex III/IV 밖의 제품에 대해 추가 조화 유럽표준을 개발할 표준화 요청을 준비하는 방향을 명시한다. 문서가 예시로 언급하는 분야는 다음과 같다.

- 철도
- 기계류
- 승강기
- 농업기계
- 인공지능 시스템
- 태양광 인버터

문서의 목적은 이들 분야 제품의 CRA Annex I 필수 사이버보안 요구사항을 구현할 수 있도록 시험방법과 적합성 증거를 포함하는 표준을 마련하는 것이다.

**LS메카피온 적용 관점:** 서보드라이브가 독립 제품으로 CRA Annex III/IV의 중요·중요(critical) 제품 카테고리에 해당하지 않더라도, 기계류 제품군에 대한 추가 표준화 활동이 향후 적용될 수 있는지 계속 추적해야 한다. 다만 드라이브 단품이 기계류 표준의 대상인지, 완성 기계/부분완성기계에 포함되는지는 제품 경계와 intended purpose에 따라 별도로 판정한다.

공식 원문:
- Commission Notice C/2026/1695, OJ C, 19.3.2026
- https://eur-lex.europa.eu/eli/C/2026/1695/oj

### 18.3 법적 효력과 적합성 추정은 구분한다

C/2026/1695는 유럽연합 표준화 연간 작업계획을 알리는 Commission Notice다. 이 문서에 표준화 활동이 기재되었다는 사실만으로 다음 효과가 발생하지 않는다.

1. 표준이 최종 발행되었다는 의미가 아니다.
2. 해당 표준의 CRA 조화표준 지위가 확정되었다는 의미가 아니다.
3. EU 관보에 표준 참조가 인용되었다는 의미가 아니다.
4. CRA Article 27의 적합성 추정이 발생했다는 의미가 아니다.

Article 27 적합성 추정은 CRA Annex I 요구사항을 다루는 조화표준 또는 그 일부의 참조가 EU 관보에 실제로 게재된 범위에서만 검토한다. 표준 개발기관의 초안·최종 초안, M/606 요청 목록, 연간 작업계획, OJ 인용은 서로 다른 상태로 관리한다.

### 18.4 다음 표준 감사 작업

| 추적 대상 | 필수 확인 사항 | 현재 상태 |
|---|---|---|
| M/606 41개 표준 | 개별 번호·제목·수평/수직 구분·초안/공개조사/승인 상태·납기 개정 | 요청 및 총수 확인, 개별 41개 상태 미완료 |
| M/606 개정 C(2026) 7861 | 채택 문서, 발효/비수락 절차, 변경된 각 납기 | Commission 페이지에서 2026-11-10 개정 사실 확인. 상세 문서·조항별 일정 대조 진행 필요 |
| CRA OJ harmonised-standard citations | EUR-Lex/OJ에 실제 게재된 참조·제한·철회·적용 범위 | 별도 OJ 전체 감사 미완료 |
| C/2026/1695 Action 5 | 기계류 등 Annex III/IV 밖 제품의 추가 표준화 요청 채택·발행 여부와 적용 범위 | 연간 작업계획에 방향이 기재된 사실 확인. 실제 요청·표준 개발·OJ 인용은 미확정 |
| 기계류 표준과 CRA | Machinery Regulation Annex III 1.1.9/1.2.1 및 CRA Annex I 위험의 매핑 | 표준 발행 및 제품별 위험평가에 맞춰 후속 검증 필요 |

**현재 결론:** 표준화 계획은 M/606만으로 종결되지 않는다. M/606의 41개 표준과 C/2026/1695 Action 5를 별도 트랙으로 관리하고, 실제 OJ 인용이 확인되기 전까지 CRA Article 27 적합성 추정을 주장하지 않는다.

### 19.1 공식 원문 확인

Annex I는 41개 표준의 ESO adoption deadline을 표로 제시한다. 현재 저장소의 41행 M/606 매핑 CSV 및 validator의 deadline 기대값을 원문과 대조했다. 아래 날짜는 **표준화기관(ESO)의 표준 채택·제출 일정**이며 제조자에게 부과된 CRA 준수 기한이 아니다.

### 19.3 서보드라이브 관련 M/606 항목의 올바른 해석

- **항목 25 — physical and virtual network interfaces:** EtherCAT 등 네트워크/필드버스 포트가 존재한다는 사실은 인터페이스 관련 보안 요구를 위험평가에 반영할 근거가 될 수 있다. 그러나 서보드라이브 전체의 core functionality가 네트워크 인터페이스 제품이라는 뜻은 아니다.
- **항목 36 — firewalls, intrusion detection and/or prevention systems, including specifically those intended for industrial use:** 산업용 방화벽/IDS/IPS 제품 카테고리의 표준화 항목이다. 서보드라이브에 통신 포트가 있다는 이유만으로 이 제품 카테고리에 해당하지 않는다.
- **항목 28–30, 37–38 — 보안 기능이 있는 프로세서/마이크로컨트롤러/ASIC/FPGA:** 드라이브 내부에 MCU·FPGA가 존재한다는 사실만으로 해당 부품 제품군의 core functionality를 갖는다고 단정하지 않는다. 별도 시장 공급 여부, 보안 기능, 제품 경계 및 기술 설명을 확인한다.
- 나머지 수직 항목도 동일하게 제품 카테고리의 core functionality와 기술 설명을 기준으로 한다. M/606 번호는 제품분류 결과가 아니라 표준화 작업 항목이다.

### 19.4 제조자에게 미치는 영향과 법적 한계

1. M/606의 개정은 표준화기관의 산출 일정 변경이다. CRA Article 14 신고 의무 및 CRA 일반 적용일을 연장하지 않는다.
2. M/606 Annex I는 표준화 요청 문서다. 그 자체로 최종 발행된 조화표준이 아니며 Article 27 적합성 추정을 발생시키지 않는다.
3. Article 27 적합성 추정은 해당 조화표준 참조가 EU 관보에 실제 인용된 범위에서 판단한다.
4. 표준 발행 전에도 제조자는 CRA Annex I 및 Annex VII에 따라 위험평가, 보안 통제, 취약점 처리, 시험과 기술문서 준비를 진행해야 한다.

### 19.5 저장소 매핑 및 validator 확인

기존 reports/CRA_M606_ANNEX_I_SERVO_DRIVE_RELEVANCE_2026-11-17.csv는 41개 항목을 각각 기록하고 있으며, 1번·15번은 2026-11-30, 2–14번은 2027-10-30, 16–41번은 2027-01-31로 매핑되어 있다. cra_traceability.py의 fail-closed validator도 41개 행의 카테고리·관련성 클래스·제출기한을 검사한다.

이번 원문 대조에서 현재 41개 일정 매핑과 validator 기대값 사이의 날짜 불일치는 발견하지 못했다. 단, 개별 표준의 실제 초안·승인·최종 발행 진행 상태와 OJ 인용 상태는 별도 감사 대상이며 이번 확인으로 완료 처리하지 않는다.

## 20. CRA 신고 실무 — ENISA Single Reporting Platform v1.3 운영 준비

### 20.1 지금부터 적용되는 신고 의무

2026-09-11부터 CRA Article 14 제조자 신고 의무가 적용 중이다. 이 신고 의무는 CRA의 일반 사이버보안 요구사항 적용일인 2027-12-11보다 먼저 시작했다.

신고 대상은 모든 버그나 보안 취약점이 아니다. 다음 두 종류를 구분한다.

1. **적극 악용 중인 취약점(Actively Exploited Vulnerability, AEV):** 악의적 행위자가 시스템 소유자의 허가 없이 실제로 악용했다는 신뢰할 수 있는 증거가 있는 취약점이다. 취약점이 발견됐다는 사실만으로는 AEV가 아니다.
2. **제품 보안에 영향을 미치는 중대 사고(Severe Incident):** 제품의 데이터나 기능의 가용성, 진정성(authenticity), 무결성(integrity), 기밀성(confidentiality)을 심각하게 훼손하는 사고다. 심각성 판단은 CRA Article 14(5) 기준으로 기록한다.

정상적인 보안 연구·선의의 시험에서 발견됐고 악의적 실제 악용의 증거가 없는 취약점은 그 사실만으로 AEV 의무 신고 대상이 되지 않는다. 다만 내부 취약점 처리·수정·공개 절차는 별도로 필요하다.

### 20.2 신고 시계와 최종 보고서

| 단계 | 법정 기준 | 실무 조치 |
|---|---|---|
| Early Warning | 인지 후 부당한 지체 없이, 늦어도 24시간 이내 | 인지 시각, 최초 증거, 영향 제품·버전, 담당자와 CDaC를 즉시 기록 |
| 72-hour Notification | 인지 후 부당한 지체 없이, 늦어도 72시간 이내 | 일반 정보와 초기 평가, 영향·심각도, 현재 조치, 원인/위협 정보를 보완 |
| AEV Final Report | 시정·완화 조치(예: 패치)가 제공 가능해진 후 늦어도 14일 이내 | 패치/완화조치의 제공 시각, 영향 범위, 기술적 세부사항과 후속 조치를 제출 |
| Severe Incident Final Report | 72시간 신고 후 1개월 이내 | 사고 원인, 영향, 조치 및 재발 방지 결과를 제출 |

**운영 원칙:** 법정 시간은 SRP 화면의 카운터만 보고 관리하지 않는다. 제조사는 취약점·사고를 인지한 원본 시각을 별도 시스템에 보존하고, 24시간·72시간·최종보고서 시계를 독립적으로 계산한다.

### 20.3 SRP 플랫폼의 현재 기능·제약 — 2026-11-19 기준

ENISA의 공식 SRP FAQ는 2026-10-15 업데이트되었고, SRP는 2026-11-04 버전 1.3으로 업그레이드되었다. ENISA의 AR User Manual도 버전 1.3이 공개되어 있다.

- SRP는 2026-09-11부터 제조자의 Article 14 의무 신고를 지원한다.
- 현재 플랫폼은 AEV 및 중대 사고의 의무 신고를 지원한다. Article 15 자발적 신고 기능은 초기 버전에 아직 제공되지 않는다.
- 플랫폼은 영어로 제공된다(ENISA FAQ 2026-10-15 기준).
- 초기 버전에는 제조자 시스템과 직접 연결하는 API가 제공되지 않는다. 내부 티켓·취약점 관리·타임라인 자동화는 가능하지만 실제 제출은 SRP 웹 인터페이스에서 수행한다.
- Assigned Representative(AR)는 개인 EU Login 계정과 MFA가 필요하다.
- 제조자당 Primary AR은 1명, Secondary AR은 최대 20명이다. Primary AR은 제조자 연결 관리 및 Secondary AR 초대 등 관리 권한을 갖는다. Primary/Secondary 모두 권한 범위 내 신고 제출·수정이 가능하다.
- 제조자와 EU 내 주된 사업장이 있는 경우, 제품 사이버보안 관련 결정이 주로 이뤄지는 EU 주된 사업장 소재국의 CSIRT designated as coordinator(CDaC)를 선택하는 것이 일반적이다. EU 내 주된 사업장이 없다면 Article 14(7)의 대체 기준(관련 authorised representative, importer, distributor, 최종적으로 사용자 수)을 순서대로 확인한다.
- SRP에 신고하면 선택한 CDaC와 ENISA에 정보가 전달되고, CDaC가 관련 회원국 CSIRT에 전파한다. 예외적 사정에 따른 전파 지연은 CRA Article 16(2)와 Delegated Regulation (EU) 2026/881을 별도로 적용한다.

### 20.4 SRP v1.3 카운터에 관한 중요한 주의

ENISA FAQ는 2026-10-15 현재 SRP의 72시간 카운터가 24시간 Early Warning 제출 후 48시간을 더하는 방식으로 표시된다고 설명한다. 따라서 제조자가 실제로 인지한 시각을 기준으로 72시간이 아직 지나지 않았더라도, 화면에서 overdue로 표시되는 상황이 발생할 수 있다. ENISA는 향후 인지 시각 필드를 기준으로 계산하도록 수정할 계획이라고 안내한다.

또한 현재 버전에서는 AEV Final Report의 카운터가 구현되어 있지 않다. 시정·완화조치가 언제 제공 가능해졌는지에 따라 14일을 계산해야 하기 때문이다. Severe Incident Final Report 카운터는 72시간 신고 후 1개월로 표시된다.

**따라서 화면 카운터는 보조 알림일 뿐 법정 기한을 변경하지 않는다.** 인지 시각, 24시간 신고 제출 시각, 72시간 신고 제출 시각, 패치/완화조치 제공 시각, 최종보고서 제출 시각을 제조자 내부 기록으로 각각 보존해야 한다.

### 20.5 SRP 장애 시 처리

SRP가 일시적으로 사용 불가하면 ENISA FAQ는 플랫폼이 복구될 때까지 기다린 뒤 SRP를 통해 신고하도록 안내한다. 복구 전 즉시 소통할 필요가 있다고 판단하면 지정 CDaC에 직접 연락할 수 있지만, SRP가 복구된 후에는 해당 신고를 플랫폼에 다시 제출해야 한다.

장애 시 제조사 내부 절차에는 다음을 포함한다.

- 장애 확인 시각 및 화면/상태 증거 저장
- 법정 인지 시각과 신고 준비 완료 상태 유지
- 긴급 연락이 필요할 경우 지정 CDaC 연락
- 플랫폼 복구 감시 및 복구 즉시 SRP 제출
- 직접 연락과 SRP 제출의 상호 참조 및 사후 기록

### 20.6 과거 출시 제품과 통합 부품 취약점

- CRA Article 69(3)에 따라 Article 14 신고 의무는 CRA 범위에 속하는 제품 중 2027-12-11 이전에 시장에 출시된 제품에도 적용된다. 신고 의무가 시작된 2026-09-11 이후 제조자가 해당 AEV 또는 중대 사고를 인지한 경우가 기준이다. 2026-09-11 전에 이미 적극 악용 사실을 인지했던 사건을 소급해 신고하라는 의미는 아니다.
- 제품에 통합된 제3자 부품의 취약점이 완제품에서 실제 악용 가능하고 제품 보안에 영향을 미친다면, 완제품 제조자는 해당 취약점을 신고해야 한다. 그 부품 자체가 별도 제품으로 시장에 출시되었다면 부품 제조자도 자신의 제품에 대해 신고 의무가 발생할 수 있다.
- 취약점이 통합 부품에 존재하더라도 완제품에서는 악용될 수 없다면 그 완제품에 대한 AEV 의무 신고로 자동 연결되지 않는다. 다만 제조자는 부품 제조자에게 알리고 CRA Article 13(6)에 따른 조치를 검토해야 하며, 자발적 신고 가능성은 별도로 판단한다.

### 20.7 LS메카피온에 필요한 즉시 준비 항목

1. EU 시장 공급 제품별 법적 제조자와 EU 내 주된 사업장 또는 Article 14(7) 대체 기준을 확정한다.
2. Primary AR 1명과 대체·지원 Secondary AR을 지정하고, 각 개인의 EU Login/MFA 준비를 확인한다.
3. PSIRT 또는 취약점 신고 접수 채널, 24/72시간 담당자, 법무·제품개발·품질·고객지원 에스컬레이션을 정의한다.
4. 취약점 인지 시각과 증거, 영향 SKU/HW/FW 버전, 통합 부품, 악용 가능성, 심각도, 조치 상태를 기록하는 내부 양식을 만든다.
5. SRP 웹 UI 제출을 모의 훈련하고, API가 없다는 점을 반영해 수동 제출·이중 확인·증거 보존 절차를 정한다.
6. SRP v1.3의 카운터와 법정 시간 계산을 혼동하지 않도록 내부 deadline tracker를 운영한다.
7. 제품이 오래전에 출시되었더라도 2026-09-11 이후 인지한 AEV/중대 사고에 대응할 수 있도록 과거 펌웨어·부품·취약점 기록을 확보한다.

제품별 신고 책임·운영 절차는 LS메카피온의 EU 공급 구조와 실제 제품 변형을 확인한 뒤 확정한다.

## 21. LS메카피온 제품군 — 통신 인터페이스·설정 도구·ESI 지원 현황

### 21.1 왜 이 표가 CRA 분석에 필요한가?

CRA Article 2의 데이터 연결 판단과 Annex I 위험평가를 위해서는 제품에 어떤 통신 경로가 있는지뿐 아니라, 그 경로를 누가 어떤 도구로 설정·업데이트하는지도 확인해야 한다.

- **제품 인터페이스:** EtherCAT, 펄스/아날로그 지령, 기타 통신 등 드라이브와 외부 제어기·PC가 연결되는 경로
- **설정 도구:** 파라미터 읽기/쓰기, 상태 모니터링, 진단, 백업/복원에 사용하는 PC 프로그램
- **ESI 파일:** EtherCAT master가 slave 장치의 특성·객체·구성을 인식하기 위한 XML 장치 설명 파일이다. ESI 자체는 펌웨어도 아니고 보안 업데이트 메커니즘도 아니다.
- **펌웨어/OS 업데이트 도구:** 드라이브의 코드·운영 소프트웨어를 교체하는 경로다. 인증·무결성·권한·복구·롤백 통제는 별도 검증해야 한다.

## 23. M/606 ETSI 작업의 최신 공개 진행상태 확인 — 2026-11-20

### 23.1 확인 범위와 기준일

이번 확인은 2026-11-20 기준으로 공개 접근 가능한 유럽위원회 및 ETSI 공식 페이지를 다시 조회한 **부분 최신화**다. M/606 전체 41개 항목을 모두 개별 상태·최종 발행·OJ 인용까지 확인한 완료 감사가 아니다.

- 유럽위원회 CRA 표준화 페이지: 41개 표준이 M/606에 포함되며, 2026-11-10 C(2026) 7861로 일부 수평 표준 및 모든 수직 표준의 ESO 납기 3개월 연장이 공지됨. 페이지 최종 업데이트: 2026-11-12.

CEN-CENELEC 공식 뉴스룸은 2026-11-19자로 다음 두 유럽표준의 발행을 발표했다.

| 표준 | 공식 발표에서 확인한 제목/범위 | CRA 실무상 의미 | Article 27 상태 |

CEN-CENELEC는 두 문서를 국가 표준 카탈로그를 통해 구입할 수 있다고 안내한다. EN 40000-1-2는 LS메카피온 서보드라이브의 제품 위험평가, 개발 프로세스, 변경관리, 생산 및 지원기간 절차를 정리할 때 우선 검토할 가치가 있다. 다만 표준을 발행·구입할 수 있다는 사실은 특정 LS 제품이 그 표준에 적합하다는 증거가 아니며, 적용 조항별 gap analysis와 제품 증거가 필요하다.

**법적 구분:** CEN-CENELEC의 발행 발표는 유럽표준의 발행 상태를 확인하는 근거다. CRA Article 27(1)의 적합성 추정은 표준 참조가 EU 관보에 실제 게재된 범위에서만 발생한다. 이번 조사에서는 해당 두 표준의 CRA OJ 인용을 확인하지 못했으므로 적합성 추정이 발생했다고 기록하지 않는다. 다만 OJ 검색 결과만으로 장래 인용 여부 또는 다른 형식의 참조 가능성을 단정하지 않는다.

### 23.4 Article 27 적합성 추정과의 구분

CRA Article 27(1)은 관련 조화표준의 참조가 EU 관보(Official Journal of the European Union)에 게재된 범위에서 적합성 추정을 인정한다.

따라서 다음 상태를 별도 필드로 관리한다.

1. 초안 공개 또는 Public Enquiry 진행
2. ETSI 승인 절차 진행/종료
3. ETSI 최종 채택 및 발행
4. 유럽위원회 조화표준 평가
5. EU 관보(OJ)에 CRA 조화표준 참조 실제 게재
6. 게재된 표준의 적용 범위와 Annex I 요구사항 매핑

이번에 직접 확인한 ETSI 작업계획의 EN 304 625 및 EN 304 636 상세 페이지에서는 OJ 게재를 입증하는 참조가 확인되지 않았다. 그러므로 이 두 항목에 대해 Article 27 적합성 추정을 이미 확보했다고 표시하지 않는다. 이 확인 결과를 M/606 전체 41개 항목의 OJ 인용 부재로 일반화하지 않는다.

### 23.5 C/2026/1695 Action 5의 범위

2026년 연합 표준화 작업 프로그램 C/2026/1695의 Action 5는 M/606을 보완하며, Annex III/IV 밖의 제품군 중 철도, 기계류, 승강기, 농업기계, AI 시스템, 태양광 인버터 등의 CRA 표준화 공백을 다룬다.

이는 M/606 41개 항목의 일부로 합산하거나, 이미 발행된 조화표준으로 취급하지 않는다. LS메카피온 제품이 기계류 제조사의 완성 기계에 통합되는 경우에도, 드라이브 단품 CRA 적용성과 기계류·완성기계 관련 법령 및 Action 5 후속 표준의 범위를 별도로 검토한다.

### 23.6 이번 확인에서 갱신한 결론 및 남은 작업

- M/606 41개 항목의 개정 ESO 납기표는 C(2026) 7861 Annex I를 기준으로 유지한다.
- ETSI의 18개 활성 작업 목록은 2026-11-19 버전 2.3.3 스냅샷으로 기록한다. ETSI 외 CEN/CENELEC 작업의 개별 최신 상태를 대신하지 않는다.
- 서보드라이브 네트워크 인터페이스와 연관성이 높은 EN 304 625는 2026-11-05 의견 분류 평가 완료 상태로 기록한다. 다음 단계의 예정일은 최종 채택·발행·OJ 게재 완료로 오인하지 않는다.

- 다음 단계는 (1) EN 40000-1-1/-1-2의 OJ 참조 상태 및 EN 40000-1-3/-1-4 개발상태, (2) ETSI 18개 작업 각각의 최신 상태 및 OJ 필드, (3) M/606 41개 전체의 OJ 실제 게재 여부를 항목별로 교차 확인하는 것이다.

### 24.2 제품 범위: 하드웨어·펌웨어·필수 소프트웨어의 경계

공식 해설 §2.4, 문단 25는 소프트웨어가 하드웨어 제품과 별도 다운로드·별도 공급되는지보다, 제품의 의도된 목적과 합리적으로 예견 가능한 사용에서 그 소프트웨어가 기능 수행에 필요한지를 기준으로 제품 경계를 판단하도록 설명한다.

LS메카피온 분석에는 다음 구분을 적용한다.

| 요소 | 판단 질문 | 현재 처리 |
|---|---|---|
| 서보드라이브 하드웨어 | 단독으로 제품 기능을 수행하는가, 어떤 제어·통신 기능을 제공하는가 | 제품별 매뉴얼과 회로/블록 자료 확인 필요 |
| 내장 펌웨어 | 드라이브의 제어·보호·통신·업데이트 기능에 필수인가 | 제품의 디지털 제품 경계에 포함해 분석 |
| DriveCM 등 PC 도구 | 제품을 의도된 목적대로 설정·제어·운용하는 데 필수인가, 아니면 선택적 서비스 도구인가 | 설치파일·기능·지원모델 확인 전 Unknown |

| 외부 PLC/모션 컨트롤러 | 별도 제품 또는 기계 시스템 구성요소인가, 드라이브와 하나의 제품으로 시장에 공급되는가 | 계약·판매단위·시스템 설명서 확인 필요 |

별도 채널로 공급되는 소프트웨어라도 제품 기능에 필수라면 하드웨어와 함께 하나의 제품 경계에 포함될 수 있다. 반대로 함께 사용된다는 이유만으로 모든 PC 도구나 외부 PLC를 자동으로 드라이브 제품에 포함시키지는 않는다. 의도된 목적, 공급·판매 단위, 필수성, 제조자 책임을 함께 확인한다.

### 24.3 CRA 적용 범위의 데이터 연결 판단

공식 해설 §2.5, 문단 26–28은 전자회로가 있다는 사실만으로 CRA 범위에 들어가는 것이 아니라, 디지털 정보가 의도적으로 인코딩되어 송신되고 수신 측에서 정보로 해석될 수 있는 데이터 연결이 있는지를 구분한다.

- EtherCAT, Ethernet, USB, RS-485 등 실제 디지털 통신을 수행하는 인터페이스는 해당 제품의 통신 목적·프로토콜·사용 조건을 확인해 CRA 범위 증거로 평가한다.
- 단순히 전원을 공급하거나 전기적 상태를 켜고 끄는 신호만으로는 데이터 연결이라고 단정하지 않는다.
- PWM/엔코더/디지털 I/O 등은 신호의 목적과 정보 인코딩·해석 구조를 확인한 후 판단한다.

따라서 LS메카피온 제품군 전체에 대해 “전자식 서보드라이브이므로 당연히 CRA 적용”이라고만 쓰지 않는다. 제품별 통신 인터페이스와 데이터 교환 기능을 매뉴얼의 해당 페이지와 연결해 근거화한다.

### 24.4 Important/Critical 제품 분류: core functionality 기준

공식 해설 §6.1, 문단 139–145는 중요·중대 제품 분류에서 제품의 핵심 기능(core functionality)을 중심으로 판단하도록 설명한다. 핵심 기능은 제품이 의도된 목적을 달성하기 위해 없어서는 안 되는 주요 기능과 기술적 능력으로 평가하며, 단순히 다른 중요 제품 기능을 일부 포함하거나 산업용 시스템에 설치된다는 이유만으로 제품 전체가 해당 카테고리로 자동 분류되지는 않는다.

LS메카피온 서보드라이브에는 다음 판정 규칙을 적용한다.

1. 서보드라이브 단품의 의도된 목적과 주요 기술 기능을 먼저 정의한다.
2. CRA Annex III/IV 및 위임·시행 문서의 제품 카테고리 설명과 기능을 대조한다.
3. PLC, 산업용 네트워크, 방화벽, 보안 MCU 등 외부 또는 내장 구성요소의 기능을 드라이브 단품의 core functionality와 혼동하지 않는다.
4. 하나의 제품으로 통합 판매되는 시스템과 별도로 판매되는 모듈은 각 공급 경계에 따라 판단한다.
5. 홍보 문구만이 아니라 사용설명서, 기술문서, 기능 사양, 판매 단위를 상호 대조한다.

**현재 판정:** iX700M, iX7M, iX7NH 등 정확한 모델·판매 단위·핵심 기능 증거가 완성되지 않았으므로 Annex III/IV 분류는 Unknown이다. “산업용 자동화 설비에 사용된다”는 사실만으로 특정 중요 제품군에 해당한다고 확정하지 않는다.

### 24.5 펌웨어·소프트웨어 업데이트와 substantial modification

공식 해설 §4.3, 문단 103–113은 업데이트의 크기나 기술적 복잡성만으로 실질적 변경 여부를 결정하지 않고, 제품의 사이버보안 위험 수준과 의도된 목적이 어떻게 달라지는지를 기준으로 사례별 평가하도록 설명한다.

- 보안 취약점 제거가 주목적이고, 의도된 목적을 바꾸지 않으며, 새로운 위험을 도입하지 않는 보안 업데이트는 일반적으로 실질적 변경으로 보지 않는다.
- 기존 위험평가에서 고려하지 않은 새로운 인터페이스, 외부 의존성, 공격 경로, 기능이 추가되거나 위험의 가능성·영향이 커지면 실질적 변경이 될 수 있다.
- 겉보기에는 작은 기능 변경도 인증정보 저장, 원격 접근, 로그·민감정보 처리 등 새로운 위험을 만들 수 있다.
- 실질적 변경 여부와 관계없이 제조자는 지원기간 중 업데이트 보안을 확보하고 위험평가 및 기술문서를 최신 상태로 유지해야 한다.

**LS메카피온 적용:** 펌웨어 버전별 변경 이력에 기능 변경, 통신 스택, 인증·권한, 부트로더, 업데이트 경로, 암호화, 진단 로그, 원격 접근 여부를 기록한다. 각 릴리스마다 “기존 위험평가 범위 안인가?”, “새로운 공격 경로·외부 의존성이 생겼는가?”, “위험의 가능성/영향이 변했는가?”를 확인하는 변경 영향평가를 만든다.

### 24.6 보안 지원기간: 5년을 일률적인 기본값으로 보지 않음

공식 해설 §5, 문단 125–135는 CRA Article 13(8)의 지원기간을 제품의 예상 사용기간, 제품의 성격과 의도된 목적, 합리적인 사용자 기대 등을 고려해 결정하도록 설명한다.

- 5년은 모든 제품에 자동 적용되는 기본 지원기간이 아니라, 예상 사용기간이 5년보다 짧다고 입증되지 않는 경우의 최소 기준이다.
- 합리적으로 5년을 넘겨 사용하는 제품은 그 예상 사용기간에 맞춰 더 긴 지원기간을 설정해야 한다.
- 제조자는 구매 시점에 지원 종료일(최소 월·연도)을 명확하게 표시하고, 기술적으로 가능한 경우 지원기간 종료 시 사용자에게 알린다.
- 실질적 변경이 발생해도 지원기간이 자동으로 초기화되거나 연장되는 것은 아니다. 원래 예상 사용기간을 결정한 요소가 바뀌었는지를 재평가한다.

**LS메카피온 적용:** 산업용 서보드라이브의 예상 사용기간은 실제 산업 현장 운용기간, 유지보수·교체 관행, 부품 공급기간, 유사 제품의 사용자 기대를 통해 확인해야 한다. 따라서 5년으로 일괄 기재하지 말고 모델별 지원정책·단종 공지·펌웨어 보안지원 종료일을 확보한다.

### 24.7 외부 의존성 및 제3자 구성요소

공식 해설 §7.1–7.3, 문단 156–173은 제조자의 내부 위험 허용도나 비용만으로 잔여 위험을 수용할 수 없으며, 제품의 의도된 목적·합리적으로 예견 가능한 사용·운용환경을 기준으로 위험을 처리하도록 설명한다.

- 외부 네트워크·PLC·상위 제어기·운용환경에서 발생하는 위험도 제품 위험평가에서 고려한다.

### 24.9 Remote Data Processing Solution(RDPS) 판단

공식 해설 §8, 문단 178–208은 원격 데이터 처리가 CRA 제품의 일부가 되는지를 다음 세 요소로 판단하도록 설명한다.

1. 사용자 장치/운용환경에서 떨어진 곳에서 데이터 처리가 이루어지는가?
2. 그 원격 처리가 없으면 제품이 제공하는 기능 중 하나를 수행할 수 없는가?
3. 해당 원격 처리 소프트웨어가 제조자에 의해 또는 제조자의 책임 아래 설계·개발되었는가?

세 요소가 모두 충족되면 RDPS로 제품 경계에 포함해 위험평가·기술문서·적합성평가를 수행한다.

- 제조자 설계 클라우드가 원격 명령, 사용자 온보딩, 설정, 인증 또는 자동 업데이트 등 제품 기능에 필수라면 RDPS가 될 수 있다.
- 단순 통계·제품 개선 목적의 원격 텔레메트리처럼 해당 처리가 없어도 제품 기능이 수행된다면 RDPS가 아닐 수 있다. 다만 그 원격 구성요소가 만드는 위험은 제품 위험평가에서 고려한다.
- 제3자 SaaS처럼 제조자가 설계·개발한 것이 아닌 외부 서비스는 RDPS가 아닐 수 있지만, 제품 기능에 의존한다면 구성요소와 유사하게 위험을 평가하고 due diligence를 수행한다.
- 이더넷 케이블, 라우터, Wi-Fi 또는 단순 네트워크 연결은 그 자체로 RDPS가 아니다.

**LS메카피온 적용:** 현재 확보한 제조사 자료만으로 제조자 운영 클라우드·원격 제어·원격 업데이트가 존재한다고 확인하지 못했다. 따라서 RDPS는 Unknown으로 유지한다. DriveCM의 로컬 설정 기능, EtherCAT 네트워크 통신, 원격 진단/클라우드 기능을 구분해 추가 확인한다.

### 24.10 2026-09-11부터 적용되는 Article 14 보고 의무

CEN-CENELEC의 2026-11-19 공식 발표는 다음 두 유럽표준의 발행을 명시한다.

- **EN 40000-1-1** — Cybersecurity requirements for products with digital elements — Part 1-1: Vocabulary (용어·정의)
- **EN 40000-1-2** — Cybersecurity requirements for products with digital elements — Part 1-2: Principles, product risk management, and lifecycle activities (사이버보안 원칙, 제품 위험관리, 생애주기 활동)

유럽위원회 뉴스(2026-11-19)는 CRA 지원 첫 유럽표준이 2026-11-18 발행됐다고 설명하고, CEN-CENELEC 발표는 위 두 표준의 발행을 함께 알린다. 따라서 두 표준의 발행 사실은 확인하되, 표준별 표지상 개별 발행일은 별도 원문 확인 전까지 미확정으로 둔다.

### 27.2 발행과 CRA Article 27 적합성 추정은 별도 게이트

표준이 CEN/CENELEC에 의해 발행되었다는 사실만으로 CRA 조화표준이 되거나 Article 27 적합성 추정이 발생하지 않는다. CRA Article 27(1)은 해당 조화표준 참조가 EU 관보(OJ)에 게재된 범위에 대해 적합성 추정을 규정한다.

| 대상 | 유럽표준 발행 | CRA OJ 참조 | Article 27 추정 |
|---|---|---|---|
| EN 40000-1-1 | CEN-CENELEC 발표로 확인 | 이번 검색에서 직접 확인되지 않음 | 주장하지 않음 |
| EN 40000-1-2 | CEN-CENELEC 발표로 확인 | 이번 검색에서 직접 확인되지 않음 | 주장하지 않음 |
| EN 304 625 | ETSI 2026-11-19 작업계획상 의견 분류 평가 단계 | 이번 검색에서 직접 확인되지 않음 | 주장하지 않음 |

“이번 검색에서 직접 확인되지 않음”은 OJ 전체의 부재를 확정했다는 뜻이 아니다. 정확한 표준번호·판·발행기관·OJ 문서번호·게재일·제한사항을 EUR-Lex 및 OJ 원문으로 항목별 확인하기 전에는 “OJ 미게재 확정”으로 승격하지 않는다.

### 27.3 M/606 41개 OJ 전수감사 수행 기준

## 29. M/606 Annex I 41개 항목 1차 출처 전수 대조 (2026-11-20)

C(2026) 7861 final의 대체 Annex I를 기준으로 기존 매트릭스 41개 항목의 번호·주제·ESO 채택기한을 전수 대조했다. 41/41 대조 완료다. 항목 1·15는 2026-11-30, 항목 2~14는 2027-10-30, 항목 16~41은 2027-01-31이다. 이 기한은 ESO가 표준을 채택·전달하는 기한이지 제조사의 CRA 준수기한이 아니다.

| Item 15 | JT013090 | Vulnerability Handling |

이 표는 **Work Item 연결**을 확정하는 자료다. 표준의 최종 번호, 발행상태, OJ 인용까지 이 문서만으로 확정하는 것은 아니다. 해당 Work Programme은 2025-04-02 버전이므로 이후 단계 변경은 최신 자료로 별도 확인해야 한다.

CEN-CENELEC의 2026-02-23 공식 CRA webinar는 JT013090을 prEN 40000-1-3 Vulnerability handling으로 연결한다. 다만 발표 슬라이드에는 JT013091의 표준번호가 중복 오기된 부분이 있으므로, JT013091의 실제 표준번호를 이 슬라이드만으로 확정하지 않는다. 2026-11-19 CEN-CENELEC 공식 발표는 FprEN 40000-1-3의 공개가 임박했다고 알리지만, 세부 카탈로그 단계나 OJ citation field는 제시하지 않는다.

### 30.2 JT013090의 현 단계와 Article 27

현재 확보한 1차 자료로 확정 가능한 것은 다음과 같다.
- M/606 item 15 ↔ JT013090 ↔ Vulnerability Handling 연결.
- CEN-CENELEC 공식 2026-02-23 발표자료에서 JT013090은 prEN 40000-1-3으로 표기.
- CEN-CENELEC 2026-11-19 발표는 FprEN 40000-1-3이 곧 공개될 예정이라고 설명.

아직 직접 확보하지 못한 사항:
- JT013090의 최신 CEN 개별 카탈로그 레코드 및 stage code.
- 2026-11-19 Formal Vote 개시 여부의 1차 확인.
- JT013090의 공식 OJ citation 기대/비기대 필드.
- CRA 제27조상 presumption을 부여할 OJEU 게시 reference.

따라서 FprEN/투표 단계와 “citation expected”는 2차 추적자료의 lead로만 관리하고, 1차 확인 전에는 법적 효과를 확정하지 않는다. CRA 제27조 제1항은 OJEU에 reference가 게시된 조화표준 또는 그 일부에 대해서만 적합성 추정을 인정한다.

### 30.3 C(2026) 7861 Article 2의 1개월 조건

Article 2는 CEN, CENELEC 또는 ETSI가 **결정을 수령한 날부터 1개월 이내** Article 1의 개정사항을 수락하지 않는다고 표시하면 해당 결정의 적용이 중단되고 2025-02-03 버전의 C(2025)618이 계속 적용된다고 규정한다.

따라서 2026-11-10 결정일을 곧바로 수령일 또는 기간 기산일로 간주해서는 안 된다. 현재 확인된 1차 자료에서 ESO별 수령일 및 비수락 통지 원본은 확보되지 않았다. Commission 결정 전문 Recital (2)는 ESO들이 2025년 원 표준화 요청을 수락했다는 사실을 설명할 뿐, 2026년 개정에 대한 Article 2상 비수락 통지 여부를 증명하지 않는다.

현재 결론은 **“개정결정 존재 확인; Article 2 조건부 중단 가능성 존재; ESO별 수령일/비수락 통지 미확인”**이다. 1개월 기간이 이미 종료됐거나 비수락 통지가 없었다고 단정하지 않는다.

## 31. M/606 OT/IACS 수직 프로파일 6종의 최신 CENELEC 상태 및 LS메카피온 서보드라이브 기능 경계 (2026-11-20)

### 31.1 조사 목적과 판단 원칙

CEN-CENELEC 2026 Work Programme은 CLC/TC 65X가 CRA 표준화 요청 M/606에 따라 산업 자동화·제어 시스템(IACS) 및 연결된 산업 제품을 위한 수직 프로파일을 개발한다고 설명한다. 해당 작업은 CRA 수평 요구사항을 산업용 OT 환경에 구체화하는 지원 작업이다. CLC/TC 65X의 공식 업무범위도 산업 공정 계측·제어·자동화 장비와 시스템, 구성요소 및 기능의 통합, 안전·보안 측면의 조정을 포함한다.

다만 **산업용 서보드라이브라는 이유만으로 아래 여섯 제품 유형에 자동 포함되는 것은 아니다.** 실제 제품이 VPN, 네트워크 관리 시스템, SIEM, 네트워크 인터페이스 제품, 라우터/모뎀/스위치, 방화벽/IDS/IPS 중 어떤 기능을 의도된 용도로 제공하는지 확인해야 한다. 이 검토는 기능 경계와 후속 증거 수집 우선순위를 정하는 것이며, 법적 분류나 적합성 판정이 아니다.

CEN-CENELEC의 현재 CLC/TC 65X Work Programme 및 개별 프로젝트 레코드(2026-11-20 조회)에서 다음 연결을 확인했다.

| M/606 항목 | CLC 프로젝트 번호 | 현재 프로젝트 표기 | 작업 범위(공식 제목/요약) |
|---|---:|---|---|

각 프로젝트 개별 레코드는 Directive 2024/2847 및 M/606과의 연결, 프로젝트 상태 “Committee stage”, OJEU 필드 “Citation expected for Directive 2024/2847”를 표시한다. 현재 CLC/TC 65X Work Programme 목록의 상태는 여섯 항목 모두 “Under Drafting”이다. 목록상 예상 투표일은 2027-08-03으로 표시되며, 다음 단계 목표일은 프로젝트별로 2026-02-17 또는 2026-03-22로 남아 있다. 이 다음 단계 목표일은 기준일 현재 이미 지난 날짜인데도 프로젝트 상태가 “Under Drafting”으로 표시되므로, 목표일 경과를 단계 완료로 해석하지 않는다. 일정은 계획·예측치이며 최종 발행일을 보장하지 않는다.

**중요한 OJ 해석:** 개별 프로젝트 레코드의 “Citation expected”는 향후 OJEU 인용을 기대한다는 프로젝트 메타데이터이지, 이미 OJEU에 참조가 게시되었다는 뜻이 아니다. 현재 개별 레코드에는 DOR/DAV/DOA/DOP가 없고 실제 OJ citation 번호도 없다. 따라서 현재 시점에 이 여섯 초안으로 CRA 제27조 적합성 추정을 주장하지 않는다.

### 31.3 서보드라이브 제품 기능과의 조건부 대조

| 작업 | 서보드라이브와의 기능 경계 | 현재 LS메카피온 증거 기준 판단 |
|---|---|---|
| 20b VPN | 제품 자체가 VPN 터널·VPN 종단 기능을 제공하는 경우의 보안 프로파일이다. 단순 Ethernet/EtherCAT, PC 연결 또는 원격 유지보수 가능성만으로 VPN 기능이 입증되지는 않는다. | VPN 기능이 제품에 내장·제공된다는 제조사 원문을 확보하지 못했다. **현재 적용 증거 없음 / 기능 확인 전 Unknown** |
| 21b 네트워크 관리 시스템 | 네트워크 장비·노드·구성·상태를 관리하는 시스템 기능을 대상으로 한다. 드라이브 파라미터 설정·상태 모니터링용 PC 도구가 있다는 사실만으로 네트워크 관리 시스템이 되지는 않는다. | DriveCM은 설정·시운전 도구로 확인되지만, 네트워크 관리 시스템 기능·제품 경계는 입증되지 않았다. **현재 적용 증거 없음 / 기능 확인 전 Unknown** |

위 표의 “현재 적용 증거 없음”은 제조사가 해당 기능을 절대로 제공하지 않는다는 확인이 아니다. 매뉴얼·제품 사양·설치파일 원본이 확보되지 않은 상태에서 공개된 자료로 확인되지 않았다는 뜻이다. 특히 제품군 단위 공개 목록을 특정 모델의 포트·프로토콜·기능으로 일반화하지 않는다.

### 31.4 CRA 법적 효과와 표준 사용 방법

1. 여섯 prEN은 CENELEC 카탈로그에서 아직 프로젝트/위원회 단계로 표시된다. 발행된 EN 또는 OJEU 인용 표준으로 표현하지 않는다.
2. CENELEC 카탈로그의 “Citation expected”만으로 CRA Article 27의 적합성 추정이 발생하지 않는다. 실제 OJEU에 게시된 정확한 표준 참조, 적용 범위 및 제한사항을 별도 확인해야 한다.
3. 해당 프로파일은 최종 발행·인용 전에도 설계 위험분석의 참고 후보로 검토할 수 있으나, 초안의 내용이나 일정만으로 법적 의무·인증·적합성을 단정하지 않는다.
4. 이 여섯 프로파일은 M/606의 수직 표준화 작업이다. Annex III 중요·핵심 제품 등급을 자동 부여하거나, 서보드라이브를 방화벽·라우터·SIEM으로 재분류하는 근거가 아니다.

- 정확한 제품 모델/SKU, 하드웨어·펌웨어 리비전 및 EU 판매 구성
- 모델별 사용설명서·데이터시트 원본 PDF bytes, SHA-256, 표지/개정 이력 및 통신 사양 페이지
- Ethernet/EtherCAT/USB/RS-485/serial 포트별 물리 계층, 프로토콜, 역할, 기본 활성화 상태 및 외부 연결 구조
- VPN 종단·라우팅·브리징·스위칭·네트워크 관리·SIEM·방화벽/IDS/IPS 기능의 존재 여부를 명시한 제조사 답변

## 32. LS메카피온 제조사 1차 자료 인벤토리 및 모델별 인터페이스 증거 (2026-11-20)

### 32.1 조사 결과 요약

LS메카피온 공식 자료실에서 Servo 매뉴얼 목록, PEGA2/iX700M 매뉴얼 등록정보, DriveCM 1.03.2 설치자료, EtherCAT ESI 0.98 게시물 및 이전 ESI 0.96 게시물을 확인했다. 이 자료는 제품군 전체가 동일한 통신 구성을 가진다는 뜻이 아니다. 특히 DriveCM 지원 모델 목록과 EtherCAT ESI 적용 모델 목록은 서로 다르므로 별도 관리한다.

**핵심 증거 업데이트:** ESI 0.98 게시물은 EtherCAT Drive XML을 명시하고 적용 모델 11개를 열거한다. 또한 DriveCM 1.03.2 게시물의 변경 이력은 PEGA2 신규 모델 2종을 EtherCAT 및 RS-485로 구분한다. 따라서 25b(OT 물리·가상 네트워크 인터페이스)는 이전의 단순 제품군 추정이 아니라, **열거된 모델과 EtherCAT/PEGA2 EtherCAT 변형에 대해 기술적 우선 검토 후보로 확인**한다. 다만 prEN 50770-3의 최종 적용범위 전문과 각 SKU의 실제 하드웨어 구성은 확보되지 않았으므로 법적 적용 여부는 여전히 Unknown이다.

## 33. 제조사 공식 드라이브 카탈로그 및 모델별 통신 인터페이스 분류 (2026-11-20)

### 33.1 통신 가이드와 모델코드 증거

- **iX7NH — Modbus TCP:** 공식 가이드북 “iX7NH Modbus_TCP 통신 테스트(API)”가 등록되어 있다. PDF 1.3 MB, iX7NH_TCP_API.zip 69.8 MB, x64.zip 44.6 KB 및 APIv1.02 PDF 1.5 MB(2026-01-20 파일일)가 게시되어 있다. EtherCAT과 Modbus TCP가 동일 SKU에서 동시 지원되는지, 별도 옵션/펌웨어인지, 물리 포트가 공용/전용인지는 미확정이다.
- **L7P — Modbus RS-422:** 공식 가이드북은 L7P Modbus_RS-422 통신 테스트 API를 명시한다. PDF 1.2 MB(2025-05-14), L7P_RS422_API.zip 69.9 MB 및 x64.zip 44.6 KB가 등록되어 있다. 이는 RS-422 직렬 통신/API 증거다. RS-422만으로 라우터·스위치·VPN 제품으로 재분류하지 않으며, prEN 50770-3의 물리·가상 네트워크 인터페이스 정의에 포함되는지는 최종 전문 확인이 필요하다.
- **iX700M — CE 모델코드 예시:** 제조사 인증서 목록은 iX700MD1-B-150B를 예시로 든다. D1은 1축 Drive Unit, B는 480 Vac, 150은 15 kW, 마지막 B는 BiSS-C 엔코더 유형이다. CE DoC 첨부 메타데이터만 확인했으며 PDF 본문은 검토하지 않았다.

### 33.2 ESI 0.98과 제품 카탈로그의 모델명 차이

2025-07-15 게시된 ESI 0.98은 L7NH, Pegasus, PHOX, L7NHF, L7N, GEM, SMT, L7MMT, iX7NH, iX7M, iX7MD를 열거한다. 현재 카탈로그에는 iX700M 및 L7NHA/L7NHB도 EtherCAT 통신형으로 표시되지만 ESI 0.98의 세부 모델명과 완전히 일치하지 않는다. ESI 게시 이후 모델코드 변경, 계열 공용 파일 또는 별도 ESI 버전 가능성이 있으므로 ESI 목록 부재를 미지원 증거로 삼지 않고, 카탈로그 표기만으로 특정 SKU의 ESI 호환성을 단정하지도 않는다. 제조사에 판매 SKU별 최신 ESI와 Vendor ID/Product Code/Revision 호환표를 요청한다.

### 33.3 CRA M/606 25b 판단 업데이트

- iX700M, iX7M, iX7NH, L7NHA, L7NHB, L7NHF는 OT 네트워크 인터페이스 기능의 기술적 검토 대상이다.
- iX7NH Modbus TCP 가이드는 별도 TCP 통신 경로의 추가 증거지만 동일 SKU 동시 지원 여부는 미확정이다.
- PEGA2 EtherCAT 변형은 DriveCM 변경 이력에 근거한 후보이며 SKU/옵션 확인이 필요하다.
- L7P Modbus RS-422는 직렬 통신 증거로 별도 기록한다. prEN 50770-3 범위 포함 여부는 Unknown이다.
- L7PA/L7PB/L7C/L7SA/L7SB 펄스형 제품은 EtherCAT 통신형과 같은 경로로 묶지 않는다.
- VPN, NMS, SIEM, router/modem/switch, firewall/IDS/IPS 기능은 이번 자료에서 입증되지 않았다.

### 33.4 후속 확인 및 공식 출처

1. EtherCAT 모델별 SKU·매뉴얼·ESI·펌웨어·포트표 확보
2. iX7NH EtherCAT 및 Modbus TCP 동시 지원 여부, 포트/옵션/펌웨어 차이 확인
3. L7P RS-422 물리계층·Modbus RTU/ASCII 여부·접근제어 확인

### 35.3 CRA 관점에서 왜 중요한가?

1. **제품 식별 및 기술문서 완전성:** 제품명만이 아니라 정확한 SKU, 하드웨어 리비전, 펌웨어, 통신 옵션, ESI/설정도구 버전을 연결해야 기술문서가 실제 판매 제품과 일치한다.
2. **공급·업데이트 경계:** DriveCM MSI, ESI XML, DFU, 펌웨어 이미지가 서로 다른 배포물이다. 각각의 배포 주체, 무결성 검증, 서명, 버전 호환성, 취약점 수정 이력을 별도로 추적해야 한다.
3. **취약점 대응:** 릴리스 노트의 연결 오류 수정이나 시작 오류 수정은 소프트웨어 변경 증거일 뿐, 보안 취약점 수정이라고 볼 수 없다. 보안 권고문·CVE·수정 내역과 연결되는지 확인해야 한다.
4. **사용자 안내와 지원기간:** L7S/L7N 단종 안내는 제품 지원정책을 추가 확인해야 할 단서다. 단종 여부만으로 CRA 지원기간의 종료일 또는 취약점 처리 의무 종료를 추정하지 않는다.
5. **공급망 및 무결성:** ESI XML/MSI/PDF의 게시 파일명·크기 확인과 실제 bytes·SHA-256·전자서명 검증은 별도 단계다. 현재 원본 다운로드가 실패하여 파일 무결성 검증은 미수행이다.

| DriveCM 펌웨어 변경 절차에 downgrade 경로/상황이 존재했음 | 릴리스 노트의 표현으로 확인되는 기능 동작 단서 |
| 모든 모델·펌웨어에서 downgrade가 허용됨 | 미확인 |
| downgrade가 인증된 사용자만 수행할 수 있음 | 미확인 |
| 펌웨어 이미지의 전자서명·암호학적 무결성을 검증함 | 미확인 |
| 취약 버전 또는 금지 버전으로의 downgrade를 차단하는 anti-rollback 정책이 있음 | 미확인 |
| 이 오류 수정이 보안 취약점 패치임 | 근거 없음. 일반 기능 오류 수정으로만 기록 |

**중요한 구분:** downgrade 자체가 항상 금지되어야 한다고 단정하지 않는다. 현장 복구·호환성 때문에 이전 버전 복귀가 필요할 수 있다. 핵심은 제조자가 승인한 버전 범위, 권한, 이미지 진위성·무결성 검증, 취약 버전 차단, 실패 복구와 감사 추적을 위험평가에 맞게 설계했는지 확인하는 것이다.

### 36.3 CRA 검증 항목으로 전환

1. **허용 버전 정책:** 모델·하드웨어 리비전별 허용 펌웨어 버전과 금지/취약 버전 목록이 있는가?
2. **downgrade 승인:** downgrade에 별도 인증·권한·물리적 접근 또는 서비스 모드가 필요한가? 기본 설정은 무엇인가?
3. **이미지 검증:** 구버전 이미지도 전자서명 또는 MAC 검증을 통과해야 하는가? 서명 검증 실패 시 설치를 거부하는가?
4. **anti-rollback 예외:** 복구 목적 downgrade와 알려진 취약 버전으로의 복귀를 어떻게 구분하는가? 예외 승인·기록은 남는가?
5. **복구 및 감사:** 전원 차단·통신 단절·잘못된 이미지에서 복구가 가능한가? 누가 어떤 버전을 설치했는지 로그가 남는가?
6. **도구/드라이브 경계:** 이 동작은 DriveCM, 별도 DFU Downloader, 드라이브 부트로더 중 어느 구성요소가 수행하는가? 각 도구 버전과 지원 SKU는 무엇인가?

이 질문은 CRA Annex I Part I의 취약점 처리·보안 업데이트 요구를 제품별로 검증하기 위한 증거 요청이다. 릴리스 노트 하나만으로 해당 요구의 충족 또는 미충족을 판정하지 않는다.

### 37.3 구판 Ver1.1에 기재된 인증정보 기본값 — 최우선 제조사 확인 항목

**A. EtherCAT FoE 펌웨어 다운로드 비밀번호**

Ver1.1 매뉴얼의 FoE 절차는 상위제어기가 파일명과 password를 전송하고 드라이브가 이름·비밀번호 일치 여부를 확인한다고 설명한다. 같은 절차의 다운로드 비밀번호 입력값으로 '00000000'을 명시한다.

이 사실은 Ver1.1 매뉴얼의 문서화된 값이다. 모든 장치에 공통으로 적용되는지, 장치별로 바꿀 수 있는지, Ver1.7 또는 현행 펌웨어에서 유지되는지, 암호화·재전송 방어가 있는지는 확인되지 않았다. 따라서 이를 현행 제품의 확정 취약점이나 모든 기기의 공통 비밀번호라고 단정하지 않는다.

**B. 내장 웹서버 로그인 기본값**

Ver1.1 매뉴얼은 웹서버 로그인용 Object Dictionary 항목을 다음과 같이 설명한다.

| 오브젝트 | 기능 | Ver1.1 매뉴얼의 초기값 | 접근성 |
|---|---|---|---|
| '0x2420' | Webserver ID | 'ID' | RW, 저장 가능 |
| '0x2421' | Webserver Password | 'PASSWORD' | RW, 저장 가능 |

매뉴얼은 웹서버 로그인 시 이 ID와 Password를 입력하도록 안내한다. 또한 웹서버 UI의 기능 목록에는 Manual JOG, Program JOG, Object Read/Write, Parameter Save to Memory, Firmware Upgrade, Return to Factory Set 등이 포함된다. 즉 단순 상태 조회 화면이 아니라 운전·설정·업데이트에 영향을 줄 수 있는 관리 인터페이스다.

이 역시 Ver1.1 문서의 초기값일 뿐, 현행 Ver1.7/현행 펌웨어에서 같은지 확인되지 않았다. 초기값 강제 변경, 기기별 고유 자격증명, 사용자별 권한, 로그인 시도 제한, 세션 만료, 자격증명 저장 방식은 문서만으로 확정할 수 없다.

### 37.4 CRA 및 보안 설계 관점의 해석

1. **공격면이 여러 개다:** USB OTG, EtherCAT FoE, PC용 DriveCM, 내장 웹서버/Ethernet은 서로 다른 진입 경로다. 하나의 업데이트 도구만 시험해서 제품의 업데이트 보안을 확인했다고 볼 수 없다.
2. **인증정보는 버전·제품별로 관리해야 한다:** 구판 문서에 명시된 FoE/Webserver 초기값이 현재 펌웨어에도 존재하는지, 모든 장치 공통인지, 강제 변경되는지 제조사 확인이 필요하다.
3. **웹서버는 관리 인터페이스다:** Ver1.1 문서에 표시된 JOG·Object Read/Write·Firmware Upgrade·Factory Reset 기능 때문에, 웹서버 접근통제와 네트워크 노출 경계는 보안 위험평가에서 우선 확인해야 한다. 다만 문서에 접속 구조가 나온다는 사실이 인터넷에 직접 노출된다는 뜻은 아니다.
4. **전송 보안은 별도 검증이다:** 검토한 Ver1.1 페이지에서 HTTPS/TLS 설명을 확인하지 못했으나, 이것만으로 실제 구현에 TLS가 없다고 단정하지 않는다. 현행 펌웨어의 실제 프로토콜·암호화·인증·세션 보호를 확인해야 한다.
5. **업데이트 무결성·복구:** USB/FoE/DriveCM/Webserver 각 경로에서 이미지 서명, 해시/MAC 검증, 하드웨어·펌웨어 호환성 검사, downgrade 제한, 전원 차단 복구, 업데이트 감사로그를 확인해야 한다.

### 37.5 제조사에 요청할 P0 질문

- Ver1.7 매뉴얼과 최신 펌웨어에서 USB OTG/FoE/DriveCM/Webserver 네 경로가 모두 지원되는가? 모델·하드웨어 리비전·펌웨어별 지원표는 무엇인가?
- FoE password '00000000'은 Ver1.1 문서의 예시/기본값인가? 기기별 고유값인가? 변경·비활성화할 수 있는가? 현행 펌웨어에서도 사용되는가?
- Webserver ID/PASSWORD 기본값 'ID'/'PASSWORD'가 현행 버전에도 존재하는가? 첫 사용 시 변경을 강제하는가? 기기별 고유 자격증명 또는 사용자 역할이 있는가?
- FoE와 Webserver 인증정보가 네트워크에서 평문으로 전달되는가? HTTPS/TLS 또는 상호 인증을 지원하는가? 재전송 방어·로그인 시도 제한·세션 만료가 있는가?
- Webserver의 JOG, Object Read/Write, Firmware Upgrade, Factory Reset 권한을 역할별로 분리할 수 있는가? 비활성화·접근 IP 제한·감사로그 기능이 있는가?
- 네 업데이트 경로 각각에서 서명된 펌웨어 검증, anti-rollback, 손상 이미지 거부, 실패 복구가 동일하게 적용되는가?

### 37.6 증거 한계와 현재 판정

- Ver1.7 공식 상세 페이지와 첨부파일명·크기·첨부일은 확인했으나 PDF 다운로드는 오류로 실패했다. 최신 매뉴얼의 본문을 검토했다고 주장하지 않는다.
- Ver1.1은 PDF 텍스트 파싱으로 업데이트·인증정보 부분을 검토했으나 원본 bytes와 SHA-256은 확보하지 못했다.
- 실제 장치 로그인, FoE 업데이트, USB OTG, DriveCM, 웹서버 접근, 자격증명 변경, HTTPS/TLS, 서명검증, downgrade, anti-rollback 또는 복구 시험은 수행하지 않았다.
- 구판의 초기 인증정보가 현행 버전에 유지된다는 증거는 없다. 제조사 답변과 최신 매뉴얼/펌웨어 확보 전까지 **현행 자격증명 상태 Unknown, update security Unknown, security tests Not Run**으로 유지한다.

**결론:** iX7NH는 매뉴얼 Ver1.1 기준 여러 업데이트 경로와 강력한 관리기능을 가진 내장 웹서버를 문서화하고 있다. 이 때문에 CRA 보안 검토에서 업데이트 경로별 인증·무결성·복구와 웹서버 기본 자격증명을 P0 증거 요청으로 올린다. 단, 최신 Ver1.7 확인 전에는 이를 현행 제품의 확정 취약점으로 분류하지 않는다.

자료에서 확인한 기능은 다음과 같다.

- **USB OTG:** 드라이브 파라미터 백업·복원(드라이브↔USB 메모리), 알람 이력 백업(드라이브→USB 메모리), 펌웨어 업데이트(드라이브←USB 메모리).
- **EtherCAT:** FoE 펌웨어 다운로드, EoE를 통한 UDP 파라미터 설정·조정·보조 기능·파라미터 복사, CoE/CiA 402 드라이브 프로파일.
- **Ethernet/웹:** EtherCAT 외 Modbus TCP 지원을 표기하고, 내장 웹서버를 통해 별도 DriveCM 없이 웹브라우저 설정 및 Ethernet 원격 시운전을 지원한다고 설명한다.
- **물리 인터페이스:** EtherCAT 100BASE-TX, RJ45 2포트, 노드 간 최대 100m, 최소 DC 주기 125µs를 표기한다.
- **USB:** USB 2.0 Full Speed 및 OTG 2.0 규격, PC 또는 USB 저장매체 연결을 표기한다.
- **안전 기능:** STO1/STO2 입력 2채널과 EDM 출력 1채널을 표기한다.

공식 자료 URL: https://sol.ls-electric.com/uploads/document/16389370233610/iX7NH%20Series_KR_202104.pdf

### 38.3 STO 기능과 사이버보안의 구분

자료는 STO 입력 2채널과 EDM 출력 1채널을 명시한다. 이는 안전기능의 존재를 보여주는 기능 사양 단서다. 그러나 이 표기만으로 SIL/PL 등급, 인증서 유효성, 안전 기능의 진단 범위 또는 CRA 사이버보안 적합성을 확정할 수 없다. STO는 위험한 토크 발생을 억제하는 안전 기능이고, 계정 인증·펌웨어 무결성·네트워크 접근통제의 대체 수단이 아니다.

### 38.4 업데이트 절차 자료와 제품 인증 자료의 추가 단서

제조사 소프트웨어 목록은 2025-12-24자로 “iX7NH 표준 O/S 및 업데이트 가이드영상”을 게시한 것으로 표시한다. 이는 표준 O/S와 업데이트 절차에 대한 별도 안내 자료가 존재한다는 메타데이터 증거다. 영상 본문·파일은 확보하지 못했으므로 실제 업데이트 절차나 보안 통제를 검토했다고 간주하지 않는다.

제조사 가이드북 목록에는 2026-09-14 iX7NH 교육자료, 2026-06-10 iX7NH 자료, 그리고 2024-01-29 iX7NH Modbus TCP API 테스트 가이드가 등재되어 있다. Modbus API 가이드 게시물에는 PDF 1.3MB, API ZIP 69.8MB, x64 ZIP 44.6KB, 2026-01-20 추가/갱신 표기 PDF 1.5MB가 표시된다. 첨부 원본과 코드의 실제 동작은 아직 검토하지 않았다.

또한 제조사 제품인증서 목록에는 iX7NHA 계열의 CE LVD/EMC 인증서 게시물(100W~15kW 용량 변형)과 UL 100W~5kW 시리즈 인증서 목록이 확인된다. 인증서 게시물의 존재와 파일 메타데이터는 CRA 적합성 평가, CRA Annex 분류, 제품의 필수 사이버보안 요구사항 이행 또는 취약점 처리 체계를 증명하지 않는다. CE LVD/EMC와 UL 안전/전기 인증 자료는 해당 범위의 증거로만 취급한다.

### 38.5 증거 상태 및 후속 P0

1. iX7NH Ver1.7 매뉴얼 PDF 원본 확보 후 Ver1.1 및 2021 시리즈 자료와 업데이트·통신·보안 관련 변경점 비교.

**현재 판정:** 제품별 CRA scope/classification/Annex III·IV/RDPS는 Unknown, 업데이트 보안 및 원격 인터페이스 통제는 Unknown, 보안 시험은 Not Run이다. 본 절은 공식 자료에서 확인한 기능 경계와 미검증 질문을 구조화한 것이며, 제품 취약점 또는 CRA 부적합 판정이 아니다.

## 39. iX7NH Ver1.1 공식 매뉴얼의 웹서버·Modbus TCP·업데이트 상세 검토 (2026-11-20)

### 39.1 자료의 신원과 적용 한계

LS ELECTRIC 공식 문서 서버에 게시된 **「iX7NH 사용설명서 Ver1.1」** PDF의 추출 본문을 직접 열람했다. 표지에는 iX7NH Series 및 Ver1.1이 표시되고, 파일명에는 2021-08-30 날짜가 포함된다.

- 공식 원문: https://sol.ls-electric.com/uploads/document/16401412453260/_LSMecapion_%20iX7NH_KOR_Ver1.1_210830.pdf
- 검토 위치: 웹서버 기능 제12장(인쇄 페이지 12-1~12-10), Modbus TCP 제13장(13-1 이후), 펌웨어 업데이트 부록 제15장(15-1~15-13).
- 검토 방식: 공식 PDF의 검색 가능한 추출 본문과 표·절차 설명 확인.
- 증거 한계: PDF 원본 bytes를 저장소에 확보하거나 SHA-256을 계산하지 못했다. 추출 본문 검토는 원본 파일 무결성 확보와 동일하지 않다. Ver1.1은 최신 Ver1.7과 동일한 버전이 아니다.

### 39.2 내장 웹서버: 로그인·계정 설정·펌웨어 업데이트

Ver1.1 제12장은 브라우저로 드라이브 내장 웹서버에 접속하고 로그인한 뒤 모니터링·설정·시운전 기능을 이용하는 절차를 설명한다.

- 접속 경로는 PC의 LAN 포트에서 허브/공유기 등을 거쳐 드라이브의 EtherCAT IN 포트로 연결하는 구조로 설명된다. 예시 IP는 192.168.5.5이며, 실제 주소는 드라이브 설정 Object에 따른다.
- 웹서버 로그인은 Object Dictionary의 0x2420(Webserver ID) 및 0x2421(Webserver Password)에 저장된 값을 사용한다.
- Ver1.1 표에는 두 항목 모두 STRING, RW, PDO 미할당, 저장 Yes로 기재되어 있고, 초기값도 제시되어 있다. 초기 인증정보의 정확한 문자열은 공개 저장소 문서에 재게시하지 않고 **기본값 노출(구판 문서, 값 비공개 처리)**로 기록한다.
- 해당 항목의 변경속성은 '항상'으로 표기된다. 이는 설정 변경이 가능하다는 설명이지, 최초 로그인 시 변경을 강제한다는 증거는 아니다.
- 제15장은 웹서버에 로그인한 뒤 Setup → Firmware에서 펌웨어 파일을 선택·Load·Start하는 업데이트 절차를 설명한다. 전송 중 전원·Ethernet 케이블을 분리하지 말라는 주의사항과, 중단/오류 시 전원 재투입 후 재시도하는 절차가 있다.

**보안 해석:** 웹 로그인 기능이 문서화된 사실은 확인했다. 그러나 Ver1.1의 계정 초기값이 현행 Ver1.7에도 존재하는지, HTTPS/TLS 지원 여부, 세션 보호, 계정 잠금, 역할별 권한, 변경 강제, 원격 관리 서비스 비활성화 가능 여부는 이 자료만으로 확정할 수 없다. 문서에서 HTTPS/TLS 설명을 찾지 못했다는 사실만으로 평문 HTTP라고 단정하지 않는다.

### 39.3 Modbus TCP: 포트·접속 경로·읽기/쓰기 기능

Ver1.1 제13장은 iX7NH가 EtherCAT IN 포트를 통해 Modbus-TCP Server로 동작한다고 설명한다.

- Modbus TCP 사용 조건으로 노드 주소 설정 스위치를 99로 설정하는 절차가 기재되어 있다.
- 접속 경로는 PC LAN → 드라이브 EtherCAT IN이며, 예시 IP는 192.168.5.5, 포트는 TCP 502다.
- 지원 Function Code는 1, 2, 3, 4, 5, 6, 15, 16으로 기재되어 있다. 이 목록에는 코일/레지스터 읽기뿐 아니라 단일·복수 쓰기 기능도 포함된다.
- 매뉴얼은 Function Code를 통해 Coil/Register 메모리의 값을 읽거나 쓸 수 있다고 설명한다. 다만 이 사실만으로 모든 드라이브 명령이 Modbus에서 쓰기 가능하다고 확대 해석하지 않는다. 실제 위험 명령과 파라미터 범위는 전체 주소표·권한·모드별 제한을 대조해야 한다.
- 매뉴얼의 Modbus 절에서 별도 사용자 인증 절차를 확인하지 못했으나, 문서에 절차가 없다는 이유만으로 인증이 없다고 결론 내리지 않는다. 최신 펌웨어의 실제 동작 및 별도 API 가이드 확인이 필요하다.

**CRA 보안 검증 질문:** TCP 502 서비스의 기본 활성화 조건, 네트워크 바인딩·ACL, 인증 및 세션 정책, 쓰기 가능한 주소 범위, 운전 중 위험 명령 제한, 잘못된/반복 요청 처리, 감사로그, 네트워크 분리 요구사항을 확인한다. Modbus TCP의 존재 또는 포트 번호만으로 인터넷 노출이나 취약점을 주장하지 않는다.

### 39.4 FoE·USB OTG·DriveCM·웹서버 업데이트 경로

Ver1.1 제15장은 복수의 펌웨어 업데이트 방법을 구분한다.

| 경로 | 구판 매뉴얼에서 확인한 절차 | 추가 확인이 필요한 보안 속성 |
|---|---|---|
| USB OTG | FAT32 USB의 지정 폴더에서 모델명 규칙에 맞는 BIN 파일을 읽고 Loader 조작으로 업데이트 | 서명/해시 검증, 모델·하드웨어 바인딩, 변조 거부, downgrade 제한 |
| EtherCAT FoE | BOOT 상태 진입 후 파일명과 암호를 확인하고 패킷 단위로 Flash 기록 | 인증정보의 고유성·변경·전송보호, 이미지 서명·무결성, 재전송 제한 |
| DriveCM | PC USB 연결 후 Firmware Update/Downloader를 통해 OS 전송 | 도구 배포 무결성, 사용자 권한, 이미지 검증, 실패 복구, 버전 정책 |
| 내장 웹서버 | EtherCAT IN 경유 웹 로그인 후 Setup → Firmware에서 파일 업로드·시작 | HTTPS/TLS, 세션·권한, 업로드 파일 검증, 감사로그, 실패 복구 |

FoE 절차도 BOOT 상태에서 파일명과 암호를 대조한 뒤 데이터 패킷을 Flash에 기록하는 흐름을 설명한다. 구판 매뉴얼에 기재된 초기 인증정보는 현행 장치에 적용되는지 확인되지 않았으므로 공개 보고서에는 구체 문자열을 재게시하지 않는다.

USB OTG 및 웹서버 업데이트 설명에는 파일명·전송 순서·진행 표시·전원 재투입 후 Flash 반영 절차가 있다. 그러나 해당 절차 설명만으로 암호학적 서명, 해시 검증, anti-rollback, A/B 파티션, 안전한 복구 모드가 구현되어 있다고 판단할 수 없다. 반대로 설명에 나오지 않는다는 이유만으로 해당 기능이 없다고도 단정하지 않는다.

### 39.5 증거 상태 업데이트와 다음 P0

이번 원문 검토로 **구판 Ver1.1에 한정된** 웹서버 로그인/계정 설정, Modbus TCP 서버 접속 사양 및 쓰기 기능 코드, 네 가지 업데이트 경로의 절차가 구체화되었다. 이는 기존 §37~§38의 기능 목록을 보강하는 1차 제조사 증거다.

다음 작업은 다음 순서로 진행한다.

1. Ver1.7 매뉴얼 원본을 확보해 Ver1.1의 웹서버 계정, Modbus TCP, FoE, USB OTG, DriveCM, 웹 업데이트 설명과 페이지별 차이를 대조한다.
2. 제조사 Modbus TCP API PDF/ZIP을 확보하고 실제 API 호출, 읽기·쓰기 주소, 예외처리 및 인증·접근제어 설명을 검토한다.
3. 네트워크 경로별 실제 활성 서비스, TLS, 인증, 권한, 로그, 이미지 서명·무결성, anti-rollback, 복구를 시험 계획과 증거 요청서로 분리한다.
4. 제조사에 기본 계정 변경 강제 여부, 장치별 자격증명, FoE 인증정보의 현행성, Modbus 쓰기 보호, 업데이트 이미지 검증·복구 설계를 서면 질의한다.

**판정 유지:** 본 절은 구판 매뉴얼의 기능·절차 확인이다. 최신 Ver1.7의 설정·동작, 제품별 CRA 적용성/Annex III·IV/RDPS, 현행 취약점 여부 및 보안시험 결과는 여전히 **Unknown / Not Run**이다. 장치 접속·자격증명 시험·패킷 전송 등 실제 기기 시험은 수행하지 않았다.
